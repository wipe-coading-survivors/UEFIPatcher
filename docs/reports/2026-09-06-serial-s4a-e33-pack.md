# Отчёт: S4a — пакет E33 (полный AMI TermSrc + glue v3)

> 2026-09-07, ветка `serial-console`. Кандидат собран живым движком.
> Прошивка — только владельцем; этот отчёт — хендафф к кандидату и
> протоколу приёмки. Спека §11 (мини-pre-check резерва (а)) + план
> `docs/superpowers/plans/2026-09-06-serial-s4a-termsrc-swap.md`.
> Решение владельца 2026-09-06 «идём на полный AMI» (цвет rd450x).

## 1. Кандидат

- Файл: `/tmp/serial-s4a/E33-candidate.bin`, постоянная копия
  `~/E33/E33-candidate-969aa67f.bin`.
- sha256: `969aa67fee923b1a4e86872821bfc75d1cf4d737d741b74114d1cdcc614917d6`,
  16 МиБ (0x1000000), база E5C88C6F (`refs/fw/HNX99TF_200525_original_E5C88C6F.bin`,
  sha `7e9d2544…`) — LIVE-оригинал, не E32-образ.
- Одна семантическая переменная против кандидата E32 (`8def2850…`):
  **терминальный консьюмер** — наш TerminalDxe 9E863906 (edk2) заменён
  донорским AMI TermSrc 54891A9E (rd450x, **непатченный** — пре-чек §11-3:
  несоответствие размера Setup (LIVE 0x72 ≠ ожидаемого 0x94) переводит
  все три GetVariable-чтения в дефолты: порты 0/1 enabled, 115200 8N1,
  Flow=0, терминальный тип = 1 → PcAnsi — сырой ANSI, оптимально для
  цели «цвет»). Glue обновлён до v3 (search-all терминальных GUID —
  дефолтный тег TermSrc-чайлда PcAnsi ≠ VT-UTF8, который искала v2).
  SerialIo-донор и вопросы S3 — без изменений против E32.

Состав FV1 (хвост, файлы 216→219, все state 0xF8):

| # | Модуль | Старт | Размер | sha256 |
|---|--------|-------|--------|--------|
| 1 | SerialIo (AMI, донор rd450x) 97C81E5D | 0xB63B18 | 7 675 Б | `472be948…` (= E32) |
| 2 | **TermSrc (AMI, донор rd450x, без патчей)** 54891A9E | 0xB65918 | 13 361 Б | `463a6695…` (= S0-эталон) |
| 3 | SerialConsoleGlue 1EF3A7C2 **v3** | 0xB68D50 | 41 072 Б | `19d4e4c3…` |

Плюс 2 вопроса S3 в форме 10019 (Baud Rate q512 / Terminal Type q513,
varstore 1 «Setup» 0x5D/0x5E — та же фикстура `s3_questions.json`).
TerminalDxe 9E863906 в образе **отсутствует** (замена, не добавление —
единственный терминальный консьюмер); SerialDxe 9A5163E7 отсутствует
(как в E32). Цепочка **сжимается** против E32: TermSrc 13 361 Б <
TerminalDxe 65 596 Б (span 62 120 против 114 352 Б).

Донорский TermSrc: DEPEX-секции нет (единственная секция —
GUIDED LZMA EE4E5898 на всё тело; UI «TerminalSrc» внутри сжатого
дерева); entry @0x1E30; Supports() = probe SerialIo BB25CF6F +
DevicePath (без AmiSio-требования) → биндится на чайлды донорского
SerialIo. NVRAM-переменные (SerialPortsEnabledVar 2 Б /
SioSerialPortsLocationVar 4 Б / DebuggerSerialPortsEnabledVar 1 Б)
самоинициализируются в entry @0x1E58 (SetMem нулей + SetVariable) —
в image-дефолтах rd450x их тоже нет, это фабричный путь донора
(пре-чек §11-4; NVRAM-инъекции не нужны).

Glue v3: единственное изменение против v2 — `FindTerminalChild()`
без параметра-GUID перебирает все 4 терминальных GUID
(kTerminalGuidMap; mTerminalGuid первым — детерминизм): v2 искала
только q513-выбранный GUID (дефолт VT-UTF8) и промахивалась бы по
PcAnsi-чайлду TermSrc → мёртвый синтетический fallback. После v3
q512-baud жив (SetAttributes glue последним — эмпирика E32), q513
влияет только на fallback-узел (реальный чайлд находит search-all).

- **Движковый гейт** `real_image_ops_insert_serial_s4a` (новый,
  `5f2bfb0`): живой прогон на E5C88C6F — вставки + вопросы + build;
  инварианты: окно [0xB63B18, +0xF2A8), все изменённые байты над
  0xFF-хвостом, хвостовые GUID/порядок [97C81E5D, 54891A9E,
  1EF3A7C2], отсутствие 9E863906 и 9A5163E7 в FV1, state 0xF8,
  8-выравнивание, побайтовая идентичность тел вставок фикстурам,
  TermSrc: первая секция GUIDED (DEPEX-байтов нет) + UI «TerminalSrc»
  из распакованного дерева, вопросы q512/q513 round-trip (5/4 опции,

  **466 юнит + 32 ignored-гейта зелёные** (s4a — с первого прохода:

## 3. Протокол приёмки E33 (флеш — владелец)

1. Прошивка E33 (решение и руки владельца; артефакт
   `/tmp/serial-s4a/E33-candidate.bin` или `~/E33/…-969aa67f.bin`).
2. **(a) Первый бут**: консоль жива? Баннер/бут-меню/Setup на COM
   (115200 8N1 — дефолты §11-3; тайминг-контингенси S4 неактуален —
   glue v3 = та же нотификация, что доказана E32).
3. **(b) Цвет**: ANSI-SGR в выводе — Setup-меню с атрибутами/рамками
   как на rd450x (терминал владельца в ANSI-режиме; тип PcAnsi —
   «сырой» ANSI без трансляции VT-кодов).
4. **(c) q512**: смена baud → мусор на старой скорости после ранних
   строк = действует (SetAttributes glue последним, §11-5).
5. Наблюдения (даже негативные) — дословно в вердикт-отчёт.

## 4. Контингенси (при глухом первом бута — §11-6)

- (i) Несоответствие типов узлов: байт-патч @0x2312 (01→04 =
  VT-UTF8) в PE32-теле артефакта + пересборка FFS; или q513=ANSI
  (рука владельца в Setup, без перепрошивки — если консоль хотя бы
  раз поднялась).
- (ii) SioSerialPortsLocationVar=нули глушат Start: NVRAM-инъекция
  location-var (значения снять с боевого rd450x — единственный
  источник). Отдельная задача движка, вне пакета.
- (iii) Полный патч-вариант §11-2 (19 байт + свободные оффсеты
  varstore 0x72) — если дефолты нерабочи в принципе.
- CMOS-клин исключён структурно; худший исход = глухая консоль
  (до-E30); откат = перепрошивка E32/оригинала.

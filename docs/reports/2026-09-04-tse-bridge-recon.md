# Отчёт: разведка строкового моста и структур $SPF — постановка следующего цикла

> 2026-09-04, ветка `fix/cycle6-reimplent`. Разведка по итогам E18 (матрица §6
> спеки `docs/superpowers/specs/2026-09-04-page-hijack-op-design.md`,
> отчёт `docs/reports/2026-09-04-page-hijack-op-e18.md`): «строковый мост
> §2.5 + структуры страниц §2.3, только затем — клон страницы с записями».
> Метод: побайтовый разбор оригинала
> `refs/fw/HNX99TF_200525_original_E5C88C6F.bin` (извлечение $SPF и PE-ресурсов
> независимым Python-парсером, /tmp/tse-bridge/), кросс-чек живым движком
> (`hii string list`, `hii question info` на оригинале). Цель — минимизировать
> риск «формально закрыли мини-цикл, а потом доделывали»: все факты ниже
> проверены минимум двумя независимыми способами.

## 1. Главный результат: строкового «моста» не существует — «108» был ошибкой разведки

HII-ресурс Setup-модуля (PE-resource `HII/1` в файле 899407D7) содержит
**один** package list `899407D7-…` из 4 пакетов: FORMS + **STRINGS(en-US,
748 строк, nextId 749)** + **STRINGS(x-AMI mapping, 96 строк, nextId 749)**
+ GUID. Кросс-чек (мой парсер ≡ `uefi-cli hii string list`, расхождений нет):

| id | текст | кто ссылается |
|---|---|---|
| 6 / 8 / 29 | «Setup» / «Main» / «Advanced» | title-id (A-поле) страниц форм 10000/10001/10002 |
| 395 (0x18B) | «PCI Subsystem Settings» | title-id страницы-жертвы 10029 и IFR FormTitle |
| **419 (0x1A3)** | **«Above 4G Decoding»** | prompt-id: IFR-вопрос q59 **и** $SPF-запись q59 |
| 420 (0x1A4) | хелп 4G-вопроса | help-id: IFR q59 **и** $SPF-запись q59 |
| 108 | «Standard Serial Port Mode» | — («Above 4G» никогда не был 108) |

Проверка «второй таблицы» закрыта отрицательно: полный скан всех 208
GUIDed-LZMA-секций образа + сырого образа — тексты «Above 4G»/«PCI Subsystem»
существуют только в Setup-модуле. Кандидат «amitseSct/собственный пакет
AMITSE» снят: AMITSE не содержит копии строк Setup (и не должен — см. §2).
Вывод: **записи $SPF, структуры страниц и IFR индексируют один и тот же
en-US строковый пакет своего формсета.** Мост §2.5 спеки закрыт как
несуществующий; «0x1A3 vs 0x6C» — артефакт ошибки подсчёта id в разведке
2026-09-04 (упомянутой в §2.5 спеки).

## 2. IFR ↔ $SPF: инвариант согласованности string-id (механизм E18)

IFR-вопрос q59 формы 10029 (@0xDD3 form-пакета, побайтово; раскладка AMI —
string-id'ы впереди qid):

```
05 91 | a3 01 | a4 01 | 3b 00 | 01 00 | 3a 00 | 10 10 ...
one_of, scoped | prompt=419 | help=420 | qid=59 | varstore-id=1 | offset=0x3A | flags
```

Полностью совпадает с выводом движка (`hii question info` — varstore Setup
id 1, offset 0x3a). $SPF-запись q59 (@0x99D8 контейнера, 72-байтовая,
f8-подпись): qid@+0=59, type@+8=6, access@+0x10=9, **help-id@+0x14=0x1A4**,
counter@+0x18, ifr-offset@+0x1C=0xDD3, **prompt-id@+0x30=0x1A3**,
fs/opt@+0x34/+0x35. Поправка к §2.2 спеки: поле «+20 varstore-id» — на самом
деле help-string-id; «+48 qid» — на самом деле prompt-string-id (qid живёт
на +0).

Массовая проверка инварианта на всём Setup-формсете:

- 34/34 type-6 записей, сматченных по (форма-спан IFR, qid):
  `s30 == IFR prompt && s14 == IFR help` — **0 расхождений**;
- 23/23 страниц с формой в IFR: A-поле@+0xE == IFR FormTitle — 0 расхождений
  (22 формы дают 23 страницы: у форм 10000/1/2 по две — вероятно, основная и
  вложенная).

**Механизм E18 (пересмотренный):** E18 перезаписал string-id только в IFR
(title 395→749, prompt 419→750, help 420→751), $SPF оставил 395/419/420.
Аппенднутые id 749–751 валидны в том же пакете (nextId был 749) — «нерезолв
в пространстве TSE» не причина исчезновения. Причина — **нарушение
инварианта согласованности IFR↔$SPF** (либо прямой сверкой id, либо матчинг
«вопрос↔запись» теряется при расхождении). Кандидаты (i)/(ii) из отчёта E18
сводятся к этому одному инварианту; отдельный диф. эксперимент для их
различения не нужен.

## 3. Уточнённая карта контейнера $SPF (0x77164 байт)

| Регион | Диапазон | Содержимое |
|---|---|---|
| заголовок | 0x000–0x060 | `$SPF`, 0x200/0x210, varstore GUID EC87D643, 0x48=размер записи, 0x60, 6 офсетов регионов @0x30, (2,3,4)@0x50, **u32@0x60 = 0xBC = 188 = число страниц** |
| таблица страниц | 0x064–0x354 | 188 возрастающих ptr на структуры страниц; **@0x354 — нулевой слот (свободное 189-е место при count-семантике)** |
| пул структур | 0x358–0x8288 | страницы и контролы вперемешку (адресуются офсетами) |
| записи 72B | 0x8288–0x5AD20 | 72-байтовые записи; 488 с f8-подписью (типы 1/3/6/8/11/13; 6/11 — вопросы с fs/opt); на регион указывает header-офсет[0] 0x7DBC |
| записи 2-го класса | 0x5AD20–0x73F0C | ~124 КБ, переменный стрид (~0x30), поля-аналоги (access 9, string-id, ifr-подобное) — вероятно записи остальных формсетов (IntelRC и др.); не декодировано |
| хвосты | 0x73F0C–0x77164 | 5 разреженных блоков; последний header-офсет = 0x77164 = длина контейнера |

**Свободного места внутри контейнера нет** (гипотеза «зазор после записей»
из промежуточных заметок — ошибка вырожденного диапазона, опровергнуто
плотностным сканом). Структура страницы (8-байтовый префикс нулей):
marker@+8 ∈ {0..5}, form-id@+0xA, **title-id@+0xE**, seq@+0x10 (≈ индекс),
B@+0x12, u32@+0x18, cnt@+0x1C, список u32@+0x20; размерная формула
`0x20+4*cnt+4` выполняется у 117/187 страниц, у 70 off-by-4 (семантика
хвостового поля/списка не до конца ясна — задача следующего цикла).
Контролы (стрid 0x40 внутри страницы): 8-байтовый префикс + {u32 n,
u32 ptr[n]} → записи 72B. Вторая индексная таблица в зоне 0x180–0x354
(значения 0x19xx–0x62xx → пул/записи) — референс не установлен.

## 4. Геометрия аддитивной вставки («новая страница»)

Сдвиги недопустимы (правило E9), но всё в контейнере адресовано абсолютными
офсетами ⇒ безопасная стратегия — **чистые аппенды в конец контейнера**
(после хвостов) + занятие нулевого слота таблицы @0x354 + bump count@0x60:

- новая запись 72B и контролы аппендятся в хвост — существующие офсеты
  (таблица, списки, header-регионы) не меняются;
- новая страница аппендится туда же, ссылается на неё новый элемент таблицы
  @0x354;
- рост контейнера ограничен только LZMA-слотом: секция 0xC2C4 при
  декомпрессате 0x7719C — запас есть, пересборка слота платой подтверждена
  (E18, оба слота);
- неизвестные, закрываемые до прошивки: (1) count- vs zero-scan-семантика
  таблицы страниц у TSE; (2) декодирование записей 2-го класса; (3) референс
  таблицы 0x180–0x354; (4) семантика marker/u18/off-by-4.

## 5. Рекомендация: следующий мини-цикл — «hijack-v2: согласованные string-id» (E19)

Прежде чем строить новую страницу, дёшево закрыть инвариант §2 на железе.
E19 = та же жертва (10029/q59), same-length правки **обеих сторон**
одними и теми же appended-id:

- IFR: title/prompt/help → 749/750/751 (как в E18);
- $SPF: title-id страницы@+0xE → 749; записи q59: prompt-id@+0x30 → 750,
  help-id@+0x14 → 751;
- fs/opt не трогаем (мертвы на этой плате, E13–E15).

Ожидание при подтверждённом инварианте: страница выживает, заголовок и
тексты = наши — «захват страницы» фактически достигнут, канал
IFR+$SPF+строки-пакет доказан end-to-end. Реализация — расширение
существующей op `hii form hijack` (3 дополнительных same-length поля в
$SPF, вся механика из page-hijack-op переиспользуется: precheck, сканер
записей, slot-fit). Опционально E19b (тот же образ, вторая жертва): в IFR и
$SPF записать **разные** строки («IFR-SRC»/«SPF-SRC») — по железу видно,
какую сторону TSE рендерит; риск выше (ломает инвариант), поэтому только
после успешного E19a.

Критерий готовности цикла «новая страница» стартовать: E19a прошит,
страница жива, тексты наши. Тогда аддитивная регистрация идёт по §4 с
предварительным декодированием пунктов (1)–(4).

## 6. Артефакты разведки (воспроизводимость)

- `/tmp/tse-bridge/extract.py` — извлечение $SPF (FFS→GUIDed-LZMA→секция
  0x18) и скан 208 LZMA-секций образа на тексты-маркеры;
- `/tmp/tse-bridge/scan_strings.py` — карта «какой блоб содержит строки»
  (Setup 0x8D1748, IntelRC/«Platform» 0x8FDC00 — HWPM-строки: 4894
  «CPU HWPM State Control», 4965 «Enable CPU HWPM»);
- `/tmp/tse-bridge/hii_res.py` — PE-resource-парсер HII (зеркало логики
  движка `pe_resource.rs`), полные id→text таблицы (`string_tables.json`);
  сечение: en-US и x-AMI пакеты идут парой с одинаковыми id (1..748);
- `/tmp/tse-bridge/correlate.py` — IFR-walker (AMI-раскладка вопроса),
  сканер записей, корреляции §2–§3;
- движок (живой, `/tmp/uefipatcher-e18.sock`): `hii string list`,
  `hii question info 899407d7-99fe-43d8-9a21-79ec328cac21:0x10:0#10029:59`
  на оригинале (image read 8f6f3dad).

## 7. Статус

- Разведка закрыта: мост §2.5 — ошибка разведки (таблица одна); §2.3 —
  картировано до уровня, достаточного для постановки E19; механизм
  отбрасывания страницы в E18 объяснён инвариантом согласованности.
- Следующий шаг (по решению пользователя): спека+план мини-цикла
  «hijack-v2» (E19a, опционально E19b), затем цикл «новая страница» по §4.
- Плата пользователя по-прежнему на E18-образе (без страницы PCI Subsystem
  Settings); E19-кандидат соберётся на том же базовом оригинале.

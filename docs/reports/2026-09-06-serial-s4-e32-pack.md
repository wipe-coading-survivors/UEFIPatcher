# Отчёт: S4 — пакет E32 (донорский resource-aware SerialIo + glue v2)

> 2026-09-06, ветка `serial-console`. Кандидат собран живым движком.
> Прошивка — только владельцем; этот отчёт — хендафф к кандидату и
> протоколу приёмки. Спека §10 (пре-чек) + план
> `docs/superpowers/plans/2026-09-06-serial-s4-serialio-swap.md`.

## 1. Кандидат

- Файл: `/tmp/serial-s4/E32-candidate.bin`, постоянная копия
  `~/E32/E32-candidate-8def2850.bin`.
- sha256: `8def285059d29acbfbabe4c83709bc8bace496e380d8252e9f27fa00568f82cc`,
  16 МиБ (0x1000000), база E5C88C6F (`refs/fw/HNX99TF_200525_original_E5C88C6F.bin`).
- Одна семантическая переменная против кандидата E31 (`d30cca1c…`):
  **продюсер SerialIo** — наш SerialDxe 9A5163E7 (фикс 0x3F8) заменён
  донорским AMI SerialIo 97C81E5D (rd450x, resource-aware). Glue
  обновлён до v2 (надмножество поведения: immediate-путь E31 +
  fallback-нотификация на установку SerialIo-протокола). TerminalDxe и
  S3-вопросы — без изменений.

Состав FV1 (хвост, файлы 216→219, все state 0xF8):

| # | Модуль | Старт | Размер | sha256 |
|---|--------|-------|--------|--------|
| 1 | **SerialIo (AMI, донор rd450x)** 97C81E5D | 0xB63B18 | 7 675 Б | `472be948…` |
| 2 | TerminalDxe 9E863906 (= S1) | 0xB65918 | 65 596 Б | `64003242…` |
| 3 | SerialConsoleGlue 1EF3A7C2 **v2** | 0xB75958 | 41 072 Б | `fd1069ac…` |

Плюс 2 вопроса S3 в форме 10019 (Baud Rate q512 / Terminal Type q513,
varstore 1 «Setup» 0x5D/0x5E — та же фикстура `s3_questions.json`).
SerialDxe 9A5163E7 в образе **отсутствует** (замена, не добавление —
единственный SerialIo-продюсер).

Донорский SerialIo: патчей нет (пре-чек §10-1); DEPEX =
PUSH(gEfiPcdProtocolGuid)+END — удовлетворён PcdDxe 80CF7257 в LIVE;
базовый адрес берёт из ресурсного списка AmiSio-чайлда GenericSio
(скрытых фиксированных баз нет) → следует за COM-переездом, если
платформа переотчётит ресурсы.

Glue v2: attach-флоу E31 (SetAttributes → ConnectController →
терминальный чайлд → append ConOut/ConIn/ErrOut) в
`AttachSerialConsole()` + регистрация протокол-нотификации на
gEfiSerialIoProtocolGuid, если в DXE-фазе SerialIo ещё нет (донор —
driver-model, стартует по BDS ConnectAll; пре-чек §10-3). Артефакты
пересобраны стендом: SerialDxe/TerminalDxe побайтово идентичны S1
(`d16b78ee…`/`64003242…`), glue v2 = новый sha (41 072 Б, размер
совпал — код уложился в выравнивание PE).

## 2. Инварианты

- **Движковый гейт** `real_image_ops_insert_serial_s4` (новый,
  `5f96610`): живой прогон на E5C88C6F — вставки + вопросы + build;
  инварианты: окно [0xB63B18, +0x1BEB4), все изменённые байты над
  0xFF-хвостом, хвостовые GUID/порядок, отсутствие 9A5163E7 в FV1,
  state 0xF8, 8-выравнивание, побайтовая идентичность тел вставок
  фикстурам, DEPEX-байты донора в re-parse, UI «SerialIo» в
  распакованном дереве, вопросы q512/q513 round-trip (5/4 опции,
  дефолт 0), save→open→save байт-стабилен. Полная real-image серия:
  **31/31 `--ignored` зелёные** (включая s2/s3-гейты против glue v2
  артефакта).
- **Независимый `hack/fv_audit.py`**: FV1 files **216→219**,
  used 0x2D3B14→0x2EF9C8 (+0x1BEB4 = 114 388 = вставка + выравнивания),
  free_tail 0x1FC4EC→0x1E0638 (−0x1BEB4); остальные тома нетронуты.
- **Байтовый дифф** против E5C88C6F: 186 427 изменённых байт, все —
  внутри трёх зон: окно вставки [0xB63B18, 0xB7F9C8), слот Setup
  [0x8D16D0, 0x8D7BF1), слот SetupData [0xA9C708, 0xAA89E4) — оба
  пересжаты (вставка IFR/строк/$SPF). **Вне зон — 0 байт.**
- Артефакт донора в тест-данных: `tests/data/serial/SerialIoAmiDxe.ffs`
  + структурный гейт `serial_io_ami_artifact_structure` (GUID/тип/
  DEPEX/LZMA-guided EE4E5898/UI/PE: AMD64, subsystem 11, TDS 0,
  entry 0xBA0; PE32 побайтово == S0-эталону при извлечении).

## 3. Протокол приёмки E32 (флеш — владелец)

1. **(a) Регрессия на дефолтах**: COM1 (0x3F8) 115200 8N1 — boot-вывод
   и полный Setup на серийной консоли, как на E31; смена Baud Rate из
   Setup (локально или по serial) сохраняется и действует.
2. **(b) Resource-aware (гейт S4)**: Serial Port 1 Configuration →
   Change Settings = «2F8, IRQ3» → сохранить → ребут. Смотреть
   **COM2 (0x2F8) 115200 8N1**: консоль там = конвейер LIVE применил
   переезд и донорный SerialIo последовал за ресурсами (гейт пройден).
   На COM1 (3F8) при этом ожидается тишина.
3. **(c) Отрицательный исход**: консоль глухая на обоих портах — не
   реанимировать образ в цикле, лечение прежнее (CMOS-джампер);
   наблюдения дословно в вердикт (это ответ на вопрос §10-4, кем
   применяется PNP0501_0_NV: если глухо — ручка пишет вхолостую,
   resource-aware-ядро при этом валидировано самим фактом работы (a)).

Контингенси:
- **Первая загрузка глухая, вторая живая** — timing-гипотеза (AMI BDS
  читает ConOut до BDS ConnectAll, нотификация glue опоздала на цикл):
  зафиксировать в вердикте, доработка glue по вердикту (ранний
  ConnectAll или ReadyToBoot-повтор).
- Если Setup недоступен по serial, но доступен локально — выполнять (b)
  локальной консолью (E31 так и делалось).
- Мусор 20–30 знаков при переинициализации — давнее поведение платы,
  не связано.

## 4. Открытое и вердикт

Вердикт E32 — за владельцем. По вердикту закрывается/уточняется S4
(аддендум спеки §7 + roadmap по прецеденту E30/E31). Резервы (решение
владельца): собственный SerialIoSioDxe на EFI_SIO_PROTOCOL (полная
независимость от донорских бинарей), полный AMI-стек TermSrc (патч-карта
§8.3-а), Terminal 7A08CB98. Паркинг E31 (флаги 0x10/0x10) сознательно
не вводился — одна переменная на кандидат.

# Отчёт: аппаратная валидация unhide на Huananzhi X99-TF (HNX99TF) — 2026-09-02

Сессия живой прошивки внешним программатором. Плата — та же, что в
июльских экспериментах `~/git/BIOS` (перенос Console Redirection,
донор Machinist MNX99MR9A). Образ базы —
`refs/fw/HNX99TF_200525_original_E5C88C6F.bin` (16 МиБ, sha256
`7e9d2544…a1c5d`).

Плейсхолдеры: E-образы и пробники — `refs/amibcp/` (вне репозитория);
рабочие файлы сессии — `/tmp/uefipatcher-smoke/` (volatile).

## 1. Исходная точка

Первый smoke движка: `hii form set-visibility 'abbce13d-…:0x10:0#901'
--visible` + `image save` (CLI → RPC → LZMA-рекомпрессия → билдер).
Форма 901 «CPU HWPM State Control» (формсет EC87D643 «IntelRCSetup»,
файл FFS ABBCE13D, PE32 → .rsrc 'HII') — единственная suppressed-форма
образа. Результат на железе: POST идёт, **видеописк «нет видеокарты»**.
Оригинал, прошитый тем же программатором, — видео есть (аппаратная
часть исключена).

## 3. Корневые причины (две, обе закрыты диффами)

### 3.1 Видеописк = LZMA-поток lzma-rs

Дифференциальная цепочка: E1 (lzma-rs + сдвиг) мёртв; E6 (чистый сдвиг,
тот же объём смещения) жив; E3/E7 (liblzma, разные раскладки, в т.ч.
движковая с ростом) живы. Все остальные байты E1 проверены: 215 из 216
файлов FV2 байт-в-байт (с учётом сдвига), заголовки/чексуммы/выравнивание
всех файлов валидны, FIT-таблица не задета (её ссылки ≥0xd70000, сдвиг
кончается на 0xd60000), DEPEX идентичен, GUIDed-заголовок идентичен.
Остаточные отличия E1 от оригинала, кроме потока: +2 нулевых байта в
хвосте декомпрессированного потока, +1 байт 0x00 в хвосте файла (оба
были и в живом E7 — невиновны), словарь 8 МиБ против 16 (кандидат в
со-факторы, но класс потока lzma-rs покрывает всё).

Фикс: параметризуемый кодировщик liblzma-класса (`compress.rs`),
LZMA1 alone + size в заголовке; свип pb/lc — pb0/lc0 сжимает этот
модуль **лучше AMI** (90 180 байт против 90 516 при том же контенте) и
позволяет вписываться в исходный слот секции (E3-стиль: минимальный дифф).

### 3.2 Пустые подписи раскрытой формы = отсутствие PRC-токенов

E7: пункт меню «CPU HWPM State Control» появился, страница открывается,
но экран пустой — два виджета `[]` без подписей (скрин пользователя;
vision-анализ скрина галлюцинировал «5 вопросов» — данные IFR ниже
истинны). Внутри формы 901 (IFR-факты):

```
FORM 901 title=4894
  SUBTITLE 4894 'CPU HWPM State Control'
  SUBTITLE 5071 ''                    (пустая by design)
  ONE_OF 4965 'Enable CPU HWPM'           qid 0x0D5F, опции: 2639 'Disable', 4967 'HWPM NATIVE MODE', 4968 'HWPM OOB MODE'
  ONE_OF 4969 'Enable CPU Autonomous Cstate' qid 0x0D60, опции: 2639 'Disable', 2638 'Enable'
```

Все строки есть в пакете `en-US`. У модуля второй string-пакет
`x-UEFI-AMI` с AMI-токенами вида `PRC0003`/`PRC11B`, и корреляция
полная: у каждой отрендеренной строки видимых форм PRC-запись есть, у
строк формы 901 (4894/4965/4969) — нет. Вендор не создавал токи для
скрытой формы. AMITSESetupData (RAW внутри файла FE612B72, дерево
`3/208/0/0`, 108-байтные записи qid@0) содержит записи 0x0D5F/0x0D60,
структурно идентичные видимым — не причина. Июльский симптом «unnamed
rows» — та же причина (строки добавлялись только в en-US).

Фикс: (a) `string_pack` — вставка SIBT-записи на конкретный id
(разрезание SKIP-пропусков: пакет с дырами); (b) `set_item_visibility` —
PRC-патч для всех строк раскрытой формы (титул/субтитлы/вопросы/опции).

Предсказания для проверки на живом E7: заголовок страницы — пустой;
внутри скобок значения `[Disable]`-типа видны (опции 2638/2639 — общие,
с токенами).

## 4. Техника дифференциальных образов (переиспользуемая)

- Вписывание в слот: свип `pb×lc×lp` (ограничение lc+lp≤4) + `MF_BT4`,
  `nice_len 273`, dict 16 МиБ; 13-байтовый заголовок alone-потока с
  ручной записью точного size (python `FORMAT_ALONE` пишет unknown-size
  + end-marker); хвост добивается нулями — декодер останавливается по
  заявленному размеру.
- Чистый сдвиг: pad-файл (type 0xF0, GUID FF…FF, 0xFF-тело, hdr-чексумма
  0x100−Σ) перед целевым файлом; сдвиг только внутри FV, за пределы
  тома не выходить (ошибка первой сборки E6 съедала хвост FV3 с
  микрокодами).
- Побайтовая верификация: карты FV (offset/size/attr/state/hdr_ck всех
  216 файлов), диф декодированных потоков, идентичность сдвинутых
  файлов, FIT-парсер (`_FIT_   ` @0xd70000, phys = off + 0xFF000000).
- Пробники сохранены: `refs/amibcp/probes/` (suppress_probe.py,
  fvmap.py, abb_probe.py, e-билдеры, извлечённые AMI-данные).

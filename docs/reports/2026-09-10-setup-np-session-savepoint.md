## 4. Раунд 7: протокол и дерево интерпретации

Протокол: розетка из сети перед каждым образом (батарейка вынута);
порядок E36v6 → E37v6; при сомнении — E32-контроль тем же протоколом.

- **Оба ботят** → искать пункт «UEFIPatcher Setup» в Serial Port 1
  Configuration на обоих: наличие/отсутствие = исходы (a)/(b) спеки §6
  (приёмка NP-E); различие E36v6-vs-E37v6 отвечает «нужна ли страница
  для рендера goto»;
- **E36v6 ботит, E37v6 висит** → токсична регистрация страницы
  (бисект полей скелета: cnt=0/B=8/seq/title-id — раунд 8);
- **оба висят** → сентинел не единственное; дамп-сравнение остальных
  полей/соседей op (раунд 8: побайтовый дамп контекста вокруг REF).

## 6. Процессные правила (выучено)

- cargo всегда `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u all_proxy …`
- движок: `rm -f "$UEFIPATCHER_SOCK"` перед стартом; глушить `pkill -x engine`
- BIOS-образы не коммитятся; фикстуры tests/data/serial/ — можно
- правило-11 (дефект плана → docs-коммит ДО реализации) — применено 4 раза
- при «висе на входе» ЛЮБОЙ дуги: контрольный рефлеш последнего
  рабочего образа + розеточный сброс ПЕРЕД выводами о кандидате
- сверять вживлённый IFR со стоком не только по структуре, но и по
  сентинел-значениям полей (дамп всех однотипных опов — одна строка python)

## 1. Артефакт E29

- `refs/amibcp/e29-hijack-v2_1-engine.bin`, 16 МиБ, sha256
  `e1da17c7c98fe939f8f81c809e272b5935fddb8613bb7671c9ec1df39f8bcb0a`
  (база — оригинал `HNX99TF_200525_original_E5C88C6F.bin`).
- **Первый полностью движковый артефакт полного рецепта**:
  `hii form unlock` (форма 10029, 1 флип хаб-REF) + 7×
  `hii question unlock` (q54–q60) + одна op
  `hii form hijack` (строки 749/750 en-US + IFR prompt/help +
  $SPF пул-контрол 420→750 + запись s14 420→750); q61 не тронут
  (составной гейт вне E12-классов).
- Побайтовая верификация (python, независимо от движка; повторно
  воспроизведена ревьюером): контейнер $SPF = оригинал + ровно 4
  байта [0x5106, 0x99ec] (обе копии help-id 420→750 — форма
  hardware-успешных E26/E28); дифф образа confined в слоты Setup и
  SetupData; длины неизменны; re-parse подтверждает семантику.

## 2. Путь к E29 (кратко)

E18-класс (строки+IFR) не видел жертву (сток-скрыта suppress-if);
серия E19–E26 доказала unlock-рецепт и хелп-канал; движковый E27
вскрыл неполноту карты каналов (хелп сток при нашем пул-контроле);
статика + дискриминатор E28 (2 байта, запись s14) показали: хелп
рендерится только когда **обе** копии help-id в $SPF (запись s14
@+0x14 и пул-контрол str-id) указывают на аппенднутый id. Итоговая
таблица: E25 (только s14) сток · E27 (только контрол) сток ·
E26/E28 (обе) наш. v2.1 вернула стадию записи s14 в op.

Правки переживают сброс дефолтов → хелп/prompt-каналы не в
NVRAM-кэше (согласуется с линией E25–E28).

## 4. Итоговая карта каналов рендера (6/6, hardware-доказаны)

| Канал | Источник |
|---|---|
| видимость страницы/вопроса | IFR suppress/grayout-if (флипы литералов, gates-слой) |
| prompt вопроса | IFR prompt-id |
| help вопроса | $SPF запись s14 **и** пул-контрол str-id (обе копии) |
| опции one_of | сток IFR |
| пункт меню + его хелп | goto ids (не трогаем) |
| заголовок страницы | $SPF title-id (не трогаем) |

Асимметрия prompt(IFR)/help($SPF×2) — архитектура AMITSE на этой
плате; op `hii form hijack` реализует её целиком.

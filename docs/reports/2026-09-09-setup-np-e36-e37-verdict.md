# Вердикт: NP-E раунд 1 — E36/E37 (v3-цепочка): вис на входе в Setup

> 2026-09-09, ветка `setup-new-page`. Прошивка E36 (`df9c38f0…`) и
> E37 (`0c4d536e…`) — владелец. Оба кандидата из pack-отчёта
> `2026-09-07-setup-np-e36-e37-pack.md`.

Наблюдения владельца дословно:

- **E36** — виснет при входе в BIOS (TUI). Serial:

```
Version 2.18.1263. Copyright (C) 2019 American Megatrends, Inc.
BIOS Date: 10/28/2019 20:28:47 Ver: GHX99014
Press <DEL> to enter setup.Press <F11> to enter boot menu.
Entering Setup...ERROR: Class:3000000; Subclass:50000; Operation: D
```

- **E37** — та же картина (тот же вывод, то же место).

## 1. Сигнатура

`ERROR: Class:3000000; Subclass:50000; Operation: D` —
**байт-в-байт сигнатура E34** (SOFTWARE/DXE_BS_DRIVER, op 0x0D;
вердикт E34, docs/reports/2026-09-07-serial-s4b-e34-verdict.md:13).
Отличие: в E34 строка печаталась **дважды** (два COM-инстанса),
здесь — **один раз**. Пост прошёл (баннер, DEL-приглашение), краш —
точно на входе TSE («Entering Setup...»), до какого-либо рендера.

## 2. Разбор: что общего у E36/E37 с E33/E34 и что от них отличается

E33/E34-класс краша (вердикт E34 §1): при входе в Setup TSE/ConSplitter
LIVE трогает SimpleTextOut/SimpleTextIn-устройства за пределами
ConOut-списка — первый вызов «лишнего» terminal-чайлда роняет машину.
E34 приписал это TermSrc-чайлду; механика класса — любой
terminal-чайлд вне ожидаемого набора.

**Корневая находка ревизии сборки:** кандидаты E36/E37 были собраны
гейтом np на **E35-цепочке (glue v3, 1EF3A7C2)**, а не на планной
**E32-цепочке (glue v2)**. План (§«Схема данных») требует «тройку s4
(SerialIo-донор, TerminalDxe, glue v2)»; гейт Task 5 переиспользовал
хелперы гейта s4c (это E35-флоу) — вместе с ними приехал v3.
Отклонение зафиксировано финальным ревью как «wording nit» —
недооценено: **glue v3 никогда не прошивался** (E35 собран, но не
шился — не понадобился после чистого E34), тогда как v2 доказан
железом (E30–E32, включая вход и рендер Setup на COM).

Отличие v3 от v2 — search-all по **четырём** терминальным GUID
(PcAnsi/VT100/VT100+/VT-UTF8; аддендум S4a §11 — v3 создавался для
сосуществования с TermSrc). Правдоподобный механизм краша: v3
цепляет/создаёт несколько TerminalDxe-чайлдов на serial-порту —
при входе в Setup TSE трогает их (вне ConOut либо через
ConSplitter-мультирежим) → воспроизводится E34-класс. Одна ERROR-строка
(против двух у E34) согласуется с одним падающим инстансом.

## 3. Гипотезы

| # | Гипотеза | Оценка | Дискриминатор |
|---|----------|--------|---------------|
| H1 | glue v3 — E34-класс токсичности terminal-чайлдов | **первичная** | флеш E35 (чистая v3-цепочка, без Setup-правок) — вис ⇒ доказано; либо бут E36v2/E37v2 — бут ⇒ доказано контрфактом |
| H2 | Setup-правки (pageless-REF E36; пустая страница E37; форма; q600/601) валят TSE на построении дерева | вторичная, замаскирована H1 | E36v2/E37v2: если и они виснут — H2 (или H3/H4) |
| H3 | varstore 2 (новая декларация IFR_VARSTORE_EFI) ломает вход TSE | низкая-средняя | бисект: форма без varstore2/вопросов |
| H4 | сдвиг FV1 (Δ=96, 187 файлов) | низкая — бут дошёл до Setup, FFS-обход сместился корректно | бисект при необходимости |

Сток-контекст для H2: goto-REF на форму без страницы (E36) нарушает
сток-инвариант 0/89 — риск был известен (ожидание по E36 — исход (b)
«стена»), но не «вис на входе». E37 регистрирует страницу по
эталонному рецепту (слот 188, B=8, cnt=0 — прецеденты 10009/10003).
Одинаковый симптом E36/E37 говорит против REF/страницы как причины
(они — главное отличие кандидатов между собой).

## 4. Решения (исполнено)

1. Гейт np переведён на планную v2-цепочку (`SerialConsoleGlue.ffs`;
   NP_SERIAL_FILES, real_image.rs) — гейты np1/np2 зелёные на v2,
   полная `--ignored`-серия не регрессировала.
2. Кандидаты пересобраны живым движком (флоу идентичен гейту):
   **E36v2** `~/E36/E36v2-candidate-b1e38008.bin` (sha256
   `b1e3800858e6ecfe58dc64d179b48a9bcc8896458ea6e39ea4b70a8602cbb302`)
   и **E37v2** `~/E37/E37v2-candidate-8e1b476c.bin` (sha256
   `8e1b476cc9644ad74eb391bd85f4d101c1164fb28688d7c0e74cade843aa1f26`).
   Валидация: fv_audit FV1 216→219 (used 0x2efa28 / free_tail
   0x1e05d8), зонный дифф — вне FV1 0 байт, порядок/GUID/тела стока
   сохранены, Δ=96 константный, тройка над 0xFF-хвостом; re-parse
   живым движком ок. Раскладка идентична v3-кандидатам (glue той же
   длины 41 072 Б); семантика страниц/REF — из гейтов np1/np2.
3. E35 (`~/E35/E35-candidate-031df12f.bin`) остаётся
   **форензик-дискриминатором H1**: чистая v3-цепочка без Setup-правок
   и без сдвига. Необязателен, если прошивается E36v2/E37v2 напрямую.

## 5. Инструкция следующего шага (владельцу)

Приоритет — **E37v2** (основной путь дуги: страница зарегистрирована,
сток-сигнал 0/89 говорит, что без страницы пункт не рендерится):
`~/E37/E37v2-candidate-8e1b476c.bin`, 16 777 216 Б, sha256 сверен.
Прошить по прецеденту E31 §5 (терминал на COM1 открыт до включения).
Исходы: (а) Setup входит, пункт «UEFIPatcher Setup» виден в Serial
Port 1 Configuration, форма открывается — гейт дуги, H1 подтверждена
контрфактом; (b) Setup входит, пункта нет — H1 подтверждена,
«стена»-класс (E16), итерация E38 по карте каналов E29; (в) вис как
E36v3 — H1 отвергнута, виноваты Setup-правки (H2/H3/H4) — бисект
следующим раундом. Откат: E32 `~/E32/E32-candidate-8def2850.bin` или
база E5C88C6F (`7e9d2544…`). NVRAM-сброс не требуется (прецедент).

> Метод: полный FV-обход двух образов (LIVE

> `refs/amibcp/450x-4g-default.bin` — оба только чтение), побайтовый разбор

## 1. Главные результаты (по неизвестным спеки §4)

**(3) «Вторая индексная таблица 0x180–0x354» — ЗАКРЫТО: её нет.** Все
188 (LIVE) / 214 (MNX) слотов @sig+0x64 — одна возрастающая таблица
валидных указателей на структуры страниц (нарушений возрастания 0; все
слоты парсятся как страницы с 8-нулевым префиксом). «Значения 0x19xx–
0x62xx» разведки-2024 — просто верхняя половина той же таблицы,
указывающая в середину пула.

**(4) Семантика полей страницы — ЗАКРЫТО:**

| Поле | Смысл | Доказательство |
|---|---|---|
| marker@+8 | класс формсета: **1 = Setup-формсет** (7B59104A), 5 (LIVE) / 2 (MNX) = внутренний формсет AMITSE (EC87D643) | 22 формы ↔ 22 marker-1 страницы (LIVE), 36 ↔ 36 (MNX), 1:1 |
| form-id@+0xA | id IFR-формы | кросс по всем REF-рёбрам |
| title-id@+0xE | строка заголовка | E24–E26 (железо) |
| seq@+0x10 | **свой индекс в таблице** | 371/371 страниц обоих образов |
| **B@+0x12** | **слот родительской страницы** (дерево) | 10000(B=0)→10001..10006(B=1); дети 10002(B=3); 10019(B=7=слот 10018); дети 10029(B=12); MNX 10028→10029/10030(B=8) |
| u32@+0x18 | константа образа (0x3a LIVE / 0x37 MNX) | одинакова у всех Setup-страниц образа |
| cnt@+0x1C / список@+0x20 | контролы (прямые указатели на записи 72B, пул-блоки, лестницы с шагом 0x48) | разбор списков страниц 10018/10019 |

**(1) count-vs-zero-scan — статически НЕ закрыто, геометрия безопасна в
обеих семантиках.** После таблицы ровно **4 нулевых байта до page[0]**
(LIVE 0x354→0x358; MNX 0x3bc→0x3c0): 189-й слот пишется в зазор без
сдвигов; при zero-scan прочтение дальше упирается в нули (префикс
page[0]). Бамп count@0x60 + занятие слота корректны для обеих трактовок.
Парсер контейнера в AMITSE не локализован (см. §4) → эмпирика E37.

**(2) Записи 2-го класса [0x5AD20..0x73F0C) — не разбиралось, не
блокирует:** наш путь целиком в главной зоне записей (типы 6/11;
S3-аппенды этой зоны доказаны железом E31).

**goto-рендер цели без страницы — сток-сигнал: страница обязательна.**
В обоих образах **0 goto-целей без страницы** (LIVE 0/31, MNX 0/58
REF-рёбер Setup-формсета). goto-вопросы при этом **не требуют
$SPF-записей** (LIVE: 25/31 без записей; 6 имеющихся — type-6). E36
(goto-only) остаётся дешёвым дискриминатором «есть ли fallback», но
основной путь — E37 (регистрация страницы).

**Эталон-прецедент нашей геометрии в стоке MNX:** 10028 «Serial Port
Configuration» → подстраницы 10029/10030 (B=8 = слот родителя, seq=9/10,
marker=1) — живое доказательство паттерна «подстраница в конфиге
серийного порта», ровно как решил владелец.

**REF IFR-раскладка (поправка разведок):** FormId u16@**+13**,
QuestionFlags@+12 (len 15). Движковый `emit_ref` уже пишет ровно так
(`ifr_builder.rs`) — P1 не требует правки кодогенерации. Ранние скрипты
(scan_ifr S3) читали +12 — их «dst» были артефактом.

## 2. Кросс-картина (LIVE; MNX аналогично)

- Setup-формсет 7B59104A (файл 899407D7, HII-resource): 22 формы,
  31 REF, 148 вопросов. $SPF: 23 Setup-страницы (22 формы + marker-4
  дубликат 10000 с cnt=96) + 165 страниц внутреннего формсета.
- Записи 72B: 389 всего, 72 с ifr-offset внутри Setup-пакета; типы
  {6: 378, 11: 11}. Вопросы с записями: 50/148 (help/дефолты — остальные
  рендерятся из IFR, согласуется с картой каналов E29).
- Дерево страниц LIVE: 10000(B=0) → Main/Advanced/…(B=1) → …(B=3) →
  10019(B=7) → [наша будущая: B=8].

## 3. Рецепт E37 (геометрия доказана, всё поверх существующих примитивов)

IFR (движок умеет): форма **0x2775** (свободен) + REF-вопрос **q0x210**
(свободен) в конец 10019 + вопросы **q0x258+** на varstore 1, офсеты
**0x72+** (занято до 0x71; q512/q513 живут на 0x5D/0x5E).

$SPF (P3, поверх `spf.rs`): клон страницы 10019 (конвенция списков
сохраняется, прецедент E31) с патчем form-id=0x2775, title-id=наша
строка, **seq=188**, **B=8**, список = прямые указатели на новые записи
72B type-6 + пул-контрол хелпа; указатель клона → слот 188 @0x354;
count@0x60 188→189; `bump_container_length`. Рост ≈ 0x24+4·N (страница)
+ 72·N (записи) + 12·N (контролы) — против LZMA-слота 0xC2C4 (запас
0x7719C, пересчёт в P4).

## 4. Дизасм AMITSE (блоб b1da0adf, 315 КБ, LIVE; частично)

- Ранний .text несёт **таблицу из 6 формсет-GUID** @0x1b10, stride 0x20
  (GUID, formid@+0x10, aux@+0x18), включая 7B59104A — диспетчер
  спец-форм по (формсет, form-id): окно 0x20971–0x209de читает
  текущую страницу (глобал 0x46f78): form-id@+0xA, marker@+8.
- Рантайм-структуры **зеркалят $SPF-лэйаут** (marker@+8, form-id@+0xA,
  cnt@+0x1C, список@+0x20); записи — рантайм-массивы с шагом **0x48**
  (@0x47130/count@0x47120 и @0x47128/count@0x47148; поиск по qid@+0).
- Сигнатура `$SPF` и GUID FE612B72 в блобе **отсутствуют** — контейнер
  резолвится через HII-регистрацию/иной модуль; первичный парсер таблицы
  страниц не локализован. Локализация парсера — отдельная сессия
  (низкий приоритет: геометрия §3 корректна в обеих семантиках чтения).

## 5. Выход фазы R (решения по спеке §4)

- (3), (4) — закрыты статикой; (1) — на эмпирику E37 (геометрия
  валидна в обеих семантиках); (2) — не блокирует.
- goto-вопрос: E36 не пропускаем (статика не доказала отсутствие
  fallback-рендера), ожидание смещено к исходу (b)/(c); E37 — основной
  путь, его геометрия готова полностью.
- P2-числа зафиксированы (§3); P1 сводится к schema-варианту + $SPF
  pull вопроса goto (запись не нужна по сток-сигналу; контрольная
  точка — E36), P3 — к патчу полей клона + слот + count.

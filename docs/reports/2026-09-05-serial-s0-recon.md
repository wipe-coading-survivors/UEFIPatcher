## 2. FV-карта и свободное место; вердикт вставки 0xB23E08 (S0.1b)

### 2.1 Метод

- `hack/fv_audit.py` (коммитится, переиспользуется S2/S3): raw-скан
  `_FVH`, PI-заголовок FV, FFS-цепочка по заголовкам (раскладка —
  UEFITool `common/ffs.h` `EFI_FFS_FILE_HEADER`: Type@0x12, Size@0x14),
  `used`/`free_tail` по концу цепочки. API `walk_fvs()` — поля
  `offset, guid, length, header_len, files, used, free_tail, pad_files`.
- Кросс-чек движком (второй способ): `session init` → `image open $LIVE`
  → `node list` (тома `type=65`, прямые file-дети тома, FreeSpace
  `type=68`). Сокет `/tmp/serial-s0/engine.sock` оставлен живым до Task 5.
- Rule-11: в плане Task 2 найдено 5 дефектов, фикс — коммит `38dfb9b`
  (до реализации): сдвиг FFS-офсетов на 2 байта (плановый код на живых
  данных выдавал отрицательные free_tail), обещанное поле `nested_in`,
  формулировка docstring, ожидание доп-FV в TSV, транспозиция GUID
  PEI-apriori. Детали — §2.5.

### 2.2 FV-карта LIVE (E5C88C6F)

| FV | offset | length | name GUID (ext-hdr) | роль | files | pad | used | free_tail |
|---|---|---|---|---|---|---|---|---|
| FV0 | 0x800000 | 0x40000 | — (нет ext) | 1 RAW-файл `CEF5B9A3-…` (NVRAM-сторе, 0x3FFB8, до конца тома) | 1 | 0 | 0x40000 | 0 |
| FV1 | 0x890000 | 0x4D0000 | `5C60F367-A505-419A-859E-2A4FF6CA6FE5` | **DXE**: DxeCore (узел 3/3/0/1, UI-имя), DXE-apriori@0x890078, **Setup@0x8D16D0**, **SetupData@0xA9C708** | 216 | 1×44 Б | 0x2D3B14 (конец 0xB63B14) | **0x1FC4EC = 2 082 028 Б** |
| FV2 | 0xDA0000 | 0x260000 | `61C0F511-A691-4F54-974F-B9A42172CE53` | **PEI**: PeiCore (5/4), PEI-apriori@0xDA0078, WdtPei/RomLayoutPei | 59 | 2 (44 Б + 1 435 800 Б) | 0x260000 | 0 |

Верификация: (1) python-аудит (`/tmp/serial-s0/fv_live.tsv`); (2) движок
`node list | grep type=65` — ровно 3 тома, offset+length совпадают
дословно (8388608/262144, 8978432/5046272, 14286848/2490368); число
прямых file-детей и pad-файлов по томам совпадает до единицы (1/0,
216/1, 59/2); `grep -c type=68` = 0 (FreeSpace движок не материализует —
free_tail эксклюзив python-аудита). free_tail FV1 подлинный:
0xB63B14..0xD60000 = 100% 0xFF (0 не-FF из 2 082 028 байт).

Вне FV вставлять нельзя: гэп 0x840000–0x890000 — 100% 0xFF (движок:
Padding type=64), гэп 0xD60000–0xDA0000 — с 0xD70000 таблица `_FIT_`
(Intel Firmware Interface Table, движок: Padding с данными), 0..0x800000
— descriptor/ME-регион. Итого 0x40000+0x4D0000+0x260000 (FV) +
0x50000+0x40000 (гэпы) + 0x800000 (низ) = 0x1000000 — 16 МБ сходятся.

### 2.3 Вердикт вставки 0xB23E08 — гипотеза (а) опровергнута

Гипотеза (а) спеки §2.3 «вставка вне диспетчеризуемого FV» — **закрыта
(опровергнута)**. Доказательства:

1. 0xB23E08 ∈ FV1 [0x890000..0xD60000) — корневой flash-том (движок,
   type=65), DXE-роли: DxeCore, DXE-apriori, 216 файлов — диспетчеризуем
   по построению. Вставка шла в свободный хвост этого тома.
2. v011: конец последнего файла FV1 = 0x890000+0x293E02 = 0xB23E02 →
   align8 → **0xB23E08** — первый свободный слот FV1 = ровно офсет
   вставки (якорь first_diff Task 1).
3. Байтовое замыкание цепочки в SERIAL_ROM: SerialIo FFS
   (`97C81E5D`, type 07 DXE_DRIVER, size 0x1E1C) @0xB23E08 → align8 →
   0xB25C28 = TermSrc FFS (`54891A9E`, type 07, attr 0x40 CHECKSUM,
   size 0x44AE) → конец 0xB2A0D6 = 0xB23E08+25 294 Б — дифф-спан Task 1
   дословно; файлов в FV1: 217 (v011) → 219 (SERIAL_ROM).
4. Исполнение подтверждено исходом: v011+пара дала мусорный COM-вывод
   [G, §1.2] — модули запускались, диспетчер их видел.
5. E5C88C6F-эра — тот же паттерн, тот же том: конец цепочки FV1 в LIVE
   0xB63B14 → align8 → 0xB63B18 = начало кластера вставок
   0xB63B18–0xB6DB58 (§1). Т.е. молчание E5C88C6F тоже не объясняется
   (а) — остаются (б)/(в)/(г)/(д).
6. Apriori не блокер: DXE-apriori @0x890078 (156 Б, 8 записей AMI-GUID)
   и PEI-apriori @0xDA0078 (236 Б) присутствуют, но по PI-семантике
   apriori упорядочивает первые запуски, не исключает прочие файлы;
   п.4 подтверждает диспетчеризацию вставленных файлов эмпирически.

Примечание: FV1 в v011 и LIVE — разные сборки (217 vs 216 файлов,
конец цепочки 0xB23E02 vs 0xB63B14), поэтому офсеты вставок эпох разные
при одном и том же паттерне «первый слот после конца цепочки».

### 2.4 Свободное место; целевой FV для S2

- Потребность S2: rd450x-экстракты 13 403 + 7 675 = **21 078 Б** +
  выравнивание (прецедент фактической вставки: 25 294 Б на пару).
- Крупнейший непрерывный `free_tail` диспетчеризуемых FV: **FV1 =
  2 082 028 Б (~99× потребности S2 21 078 Б; ~82× к прецеденту
  вставки 25 294 Б)**; FV0/FV2 заполнены (free_tail = 0).
- **Предварительное решение: целевой FV для S2 — FV1 @0x890000 (DXE,
  name 5C60F367-…)**. Критерии: диспетчеризуем (DxeCore); free_tail
  2 МБ ≥ 21 КБ + любой запас; Setup-слоты (0x8D16D0 / 0xA9C708) лежат
  в середине цепочки — вставка в хвост их не затрагивает; прецедент:
  все прошлые попытки обеих эпох вставляли ровно туда.
- `pad_files` (filler 0xF0): FV0 — 0; FV1 — 1×44 Б (структурный,
  носитель ext-заголовка @0x890048); FV2 — 44 Б (то же) + **1 435 800 Б
  tail-filler @0xE9F620** (до 0xFFDEB8, хвост тома). Легальный реюз
  возможен только для tail-filler (pad можно урезать при rebuild), но
  S2 это не требуется — он в PEI-томе, а цель S2 — DXE-модули в FV1.
- Уточнение к спеке §2.3 («свободного места не хватало катастрофически»):
  к S2-операции (append новой пары DXE-модулей в хвост FV1) дефицит не
  относится — 2 МБ свободны (0xFF-скан). Исторический дефицит — класс
  операций роста существующих слотов: правки Setup (сдвиг 188 FFS на

  первого класса; риск — целостность пересборки существующих слотов.

### 3.1 Метод

  распаковывал ни одну секцию доноров (0/233 на обоих): (а) DataOffset —

- `spf_serial.py` (§9): у обоих доноров найден Setup-пакетлист

- Второй способ (ключевые числа): инварианты против донорского IFR —
  page title@+0xE == IFR FormTitle; запись: ifr@+0x1C == позиция вопроса

### 3.5 Unknowns tse-bridge §4 — закрытие

1. **count vs zero-scan — ДА, нулевой слот есть у всех**: `u32@0x64+4*count
   == 0` при монотонно возрастающих ненулевых ptr до него: MNX @0x37C
   (count 198), rd450x @0x3BC (214), LIVE @0x354 (188). Сразу после
   слота начинается пул: первая структура — нулевая-страница p000
   (@0x380/0x3C0/0x358), первая реальная p001 form 0x2710 @0x3CC/0x414/
   0x3A4. Регистрация новой страницы = занятие слота + bump `u32@0x60`
   — подтверждено консистентностью всех трёх контейнеров.
2. **Записи 2-го класса — отдельного региона для serial нет**: все 61
   записи serial-вопросов — стандартная 72Б-раскладка в общем регионе
   записей (границы @header[0]..header[1]); отличие от F8-записей только
   sig-байт@+0x24 (п. 3.4). «Второй класс» tse-bridge (переменный стрид
   ~0x30) = смесь в том же регионе: qid-less записи не-вопросных
   элементов (MNX @0x9C88 type=3 с IFR-подобным полем 0x1109, @0x9CC8
   type=8; стрид 0x40–0x50) и записи с нулевым/вариативным sig; граница
   LIVE 0x5AD20 классы НЕ разделяет — объединённый класс F8+zero-sig
   распределён по обе стороны (1512 ниже = 389 F8 + 1123 zero-sig,
   1344 выше). Пул дополнительно содержит контролы с копиями qid/ifr
   (MNX q0x5C @0x1F6C5 — внутри 0x30-stride цепочки пула).
3. **Таблица 0x180–0x354 — это хвост той же таблицы страниц, не вторая
   таблица**: у всех трёх контейнеров вся таблица 0x64..end монотонна и
   состоит из ptr на страницы пула; «значения 0x19xx–0x62xx» tse-bridge =
   поздние страницы пула. Serial-страницы доноров ссылаются из головных
   слотов 9–15 (MNX [9,12,13,14,15], rd450x [9..15]) — зона-аналог
   (слоты 76+) на serial-семью НЕ ссылается. Для S3: ссылка на новую
   страницу живёт в слоте таблицы страниц (@0x64+4*k), никакой второй
   индекс не нужен.
4. **marker/u18/off-by-4**: `marker@+8 = 1` у всех 12 serial-страниц
   обоих доноров (и у жертвы LIVE 10029); `u18@+0x18` — НЕ маркер
   off-by-4, а плато-константа (0x3A MNX/LIVE, 0x37 rd450x);
   формула `0x20+4*cnt+4` выполняется у 5 из 12 serial-страниц, у 7
   OFF4 (реальный размер `0x20+4*cnt`, +0/4 хвост) — то же соотношение,
   что у LIVE в целом (117/187 OK, 70 OFF4): хвостовой слот
   необязателен, «off-by-4» — свойство формулы, не данных.

### 3.6 Вывод для S3: переносимая геометрия «чужой» страницы

- **Обязательные поля страницы**: 8Б нулевой префикс, `marker=1@+8`,
  form_id@+0xA, title_id@+0xE (== IFR FormTitle — инвариант: 12/12
  донорских страниц этой задачей + 23/23 LIVE из tse-bridge §2), seq@+0x10,
  cnt@+0x1C, список u32@+0x20 → контролы (0x40-stride; ptr-массивы на
  записи + строковые блоки). Плато-специфичны (копировать с образца, не
  изобретать): `u18@+0x18`, `B@+0x12`, хвостовой слот.
- **Записи**: 72Б-раскладка неизменна на всех трёх платах (qid@+0,
  type, access=9, help@+0x14, counter@+0x18, ifr@+0x1C, 01 00 01 00@+0x2C,

- **Регистрация**: zero-slot @0x64+4*count + bump count@0x60 (п. 3.5.1);

- **Эталонный донор геометрии — MNX99MR9A**: тот же билд Setup-формсета,

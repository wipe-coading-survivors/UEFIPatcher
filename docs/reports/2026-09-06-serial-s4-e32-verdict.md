## 2. Вердикт

- **Гейт S4 «AMI-консоль работает» — ПРОЙДЕН.** Донорский AMI SerialIo
  (97C81E5D, 0 патчей) диспетчеризуется, стартует на SIO-чайлде, SerialIo
  потребляется нашим TerminalDxe, консоль жива с первой загрузки.
- **(a) Регрессия — ПОДТВЕРЖДЕНА**: бут с первого раза, баннер и
  «Press DEL/F11» на COM-порту на дефолтах. Тайминг-контингенси pack §3
  («первая загрузка глухая — нотификация опоздала») **не сработал**:
  glue v2 (протокол-нотификация) успевает до чтения ConOut — BDS
  ConnectAll → донор ставит SerialIo → нотификация → attach — всё в
  одной загрузке.
- **(b) Переезд порта — консоль ПЕРЕЖИЛА**: смена Change Settings
  сохраняется, вывод продолжается на том же физическом разъёме; на
  плате распаян один COM-порт (второго нет/не найден). Позитивное
  наблюдение вывода именно на 0x2F8 при единственном разъёме недоступно
  в принципе — базовый адрес SIO внутри чипа, разъём один и тот же.
  Ключевой контраст-факт: **на E31 та же операция клинила обе консоли**
  (глухой serial, виснущий локальный TUI, лечение CMOS-джампером), **на
  E32 — ничего не клинит**. Стек устойчив к операции, убивавшей E31 —
  терапевтическая цель S4 достигнута.
- **Baud — действует на железе** (переподтверждение гейта S3(b) на
  E32-стеке): после смены значения первые строки (баннер + Press
  DEL/F11 — печать более раннего звена на 115200) читаются, далее
  «сыпется мусор» = DXE-консоль переключилась на новую скорость
  (вопрос q512 → NVRAM Setup[0x5D] → glue v2 → SetAttributes донорского
  SerialIo → UART). Смотрящий терминал остался на старой скорости.
- **Terminal Type — сохраняется, видимых отличий нет** (как на E31).
  Контраст-факт владельца: на rd450x (полный AMI-стек TermSrc) serial
  вывод **цветной**; на нашем стеке цвет/различия типов не наблюдается.
  Косметика — парковка (механизм не разбирался; кандидаты-причины не
  утверждались).
- **(c) Глухота — не наступила**, CMOS-сброс не потребовался.

**S4 ЗАКРЫТА: гейт пройден** (наблюдаемая часть (b) — с оговоркой об
одном физическом разъёме; полный позитив-тест базы 0x2F8 недоступен
аппаратно, см. §4).

## 3. Разбор наблюдений

1. **«Вывод идёт на тот же порт»** — ожидаемо и не является отказом:
   «порт» в Change Settings — это базовый IO-адрес UART внутри SIO
   (0x3F8↔0x2F8), физический разъём один и тот же; для смотрящего
   терминала поток байт не меняется. Наблюдаемо только: жива консоль
   (E32 — да) или глуха (E31 — было). Дизъюнкция причин «платформа
   переехала и донор последовал» vs «ручка пишет вхолостую» остаётся
   открытой — §4-дискриминаторы.
2. **«Мусор после первых строк» при смене baud** — то же поведение, что
   на E31 (поправка владельца оттуда же): ранняя печать фиксирована на
   115200, DXE-консоль — на настроенном baud. Не дефект.
3. **«Нет изменений» у типа терминала** — совпадает с E31; вместе с
   rd450x-контрастом (цвет) даёт парковку «косметика терминального
   рендера» без функциональной потери: значение доходит до glue
   (выбор GUID чайлда), вывод между типами не различается.

## 4. Открытые дискриминаторы (опционально, владельцем; не блокеры)

Применяет ли LIVE `PNP0501_0_NV[1]` физически (гипотезы A/B из спеки
§10-4): (A) SIO переехал на 0x2F8 и донорный SerialIo последовал за
ресурсами — тогда resource-aware доказан контрастом E31/E32; (B) ручка
пишет вхолостую, ничего не переезжает — тогда устойчивость E32
тривиальна, а E31-клин остаётся непонятым поведением (он им и записан).
Проверки без дополнительного железа:

1. После Change Settings=«2F8, IRQ3» + ребут → в ОС `dmesg | grep -i
   ttyS` (или `/proc/tty/driver/serial`): база 0x2f8 у ttyS0 = SIO
   переехал (и ОС видит новые ресурсы); 0x3f8 = не переехал.
2. В Setup после переезда строка «Device Settings IO=…h; IRQ=…» —
   отражает ли 2F8/3.
3. Наличие раннего баннера сразу после переезда: ранний вывод пишет по
   фиксированному 0x3F8 — исчезновение баннера при живой DXE-консоли
   указало бы на реальный переезд.

## 5. Статус лестницы и парковки

- **S0–S4 закрыты.** S5 (redirect) фактически продемонстрирован
  E30+E31 (Setup-экран на терминале, управление с терминала; redirect
  следует настроенному baud). Лестница Serial Console пройдена.
- Парковки (зеркало в TODO.md):
  1. Дискриминатор A/B применения PNP0501_0_NV[1] — опциональные
     проверки §4; не блокер, вывод о ресурс-устойчивости уже достигнут
     контрастом E31/E32.
  2. E31-COM-клин не воспроизвёлся на E32 (консоль жива после той же
     операции) — контраст-факт; механизм E31-клина остаётся непонятым
     поведением (паркинг E31).
  3. Терминальный рендер: тип терминала видимо инертен, цвета как на
     rd450x нет — косметика, опционально (rd450x у владельца — живой
     референс полного AMI-стека).
  4. Зеркалирование флагов `0x10/0x10` в IfrBuilder (паркинг E31) —
     при любой следующей прошивке с новыми вопросами; E32 вопросов не
     добавлял (q512/q513 регенерированы с прежними `0x00`).
- Резервы (решение владельца, отдельные планы): собственный
  SerialIoSioDxe на EFI_SIO_PROTOCOL (независимость от донорских
  бинарей); полный AMI-стек TermSrc (патч-карта спеки §8.3-а; референс
  rd450x); Terminal 7A08CB98. Ветка `serial-console` = наработка
  S2+S3+S4; мерж PR #6 — решение владельца.

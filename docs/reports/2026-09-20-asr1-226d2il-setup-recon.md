# Разведка: где 226D2IL (E3C226D2I) хранит Setup SOL/4G и как это править (2026-09-20)

Цикл-разведка после tiano-op: на 226D2IL3.50 HII пуст (questions=0,
varstores=0, strings=0) — Setup-конфигурация живёт вне IFR. Плата живая,
доступ по IPMI/SOL (креды `../IPMI-asr1.txt`, ssh `root-asr1`).

## Где конфигурация

Плата ASRock **E3C226D2I UEFI P3.50** (AMI Aptio, TSE-класс Setup-браузер).
Цепочка в образе (обе версии 3.30/3.50 идентичны по лейауту):

| Слой | Позиция |
|------|---------|
| NV-том | FV @ `0x500000` (FS GUID 8C8CE578-8A3D-4F1C-9935-896185C32DD3) |
| FFS Raw-файл | `CEF5B9A3-476D-497F-9FDC-E98143E0422C` @ `0x500048` (= `NVRAM_NVAR_STORE_FILE_GUID`, ref: UEFITool nvram.h:29), FFS-заголовок 24 байта |
| NVAR-стор | @ `0x500060`, запись `StdDefaults` (GUID 4599D26F-1A11-49B8-B91F-858745CFF824 — AMI Setup namespace) |
| Вложенный стор | данные `StdDefaults` — NVAR из 14 переменных (Setup×2, AMITSESetup, UsbSupport, PNP0501_*_NV ×4 (COM-порты SIO, 3 байта), PNP0400/0510/0604, PlatformLang, Timeout, NetworkStackVar) |
| **Главная переменная** | **`Setup` GUID EC87D643-EBA4-4BB5-A1E5-3F3E36B20DA9, 1217 байт дефолтов, @ `0x500088`** |

Формат NVAR-записи: 'NVAR' + u16 size + b24 next + u8 attrs (+ guid_index u8
| GUID 16B | имя strz) + данные; GUID-стор растёт от конца файла (ref:
UEFITool ksy/ami_nvar.ksy; парсер-однодневка `/tmp/asr-recon/nvar.py`).

Живая переменная на хосте — ровно те же 1217 байт (efivars 1221 = u32 attrs
+ данные), маппинг live↔image 1:1 по офсетам.

## Офсеты настроек (диффы живых дампов, Verify-методика)

Состояния: live1 (обе вкл, бейзлайн) → Setup-UI: обе выкл → live2 →
efivar-флипы → live3 (обе вкл). live1==live3 байт-в-байт; дифф live1↔live2 —
**ровно 2 байта**, кроме Setup-EC87D643 не меняется ничего.

| Настройка | data[] | значение | офсет в образе |
|-----------|--------|----------|----------------|
| Serial Port Console Redirection → SOL | **[1]** | 00=Disabled, 01=Enabled | **`0x500089`** |
| Above 4G Decoding | **[1141]** | 00=Disabled, 01=Enabled | **`0x5004FD`** |

Дефолты вендора: оба 00 (Disabled) — юзер включал вручную. 3.30↔3.50:
главный Setup-блоб идентичен байт-в-байт (дефолты стабильны между версиями;
правка детерминирована, офсеты совпадают в обеих версиях — проверено).

Прочее из live1↔defaults (33 байта): [34], [36] (вкл-флаги), слово @872
1333→1600, кластер 974–1044 — остальные ручные настройки; маппинг тем же
методом при надобности.

## Вердикт по пути записи

Для «испечь дефолты» достаточно **ин-плейс правки 2 байт** в raw-теле FFS
(0x500089, 0x5004FD): размер стора не меняется, NVAR-записи чексумм не
несут; движок пересобирает FFS-чексуммы (round-trip уже зелёный, tiano-гейт).
После прошивки — сброс NVRAM/Load Defaults, переменные пересеиваются из
StdDefaults (F9 на rd450x пересевал аналогично).

Компрессор Tiano для этой задачи не нужен (копия StdDefaults одна, raw).

## Наблюдения для будущей работы с ригом/платой

- Вход в Setup по SOL: промпт «Press F2 or DEL», окно ~2–3 c (время
  перебора SATA) — ловится спамом ESC+2 с 0.3 c от AMI-сплеша до GRUB.
- Пачки клавиш SOL глотает: стрелки по одной с ≥0.4 c; редро подсветки
  отстаёт до ~2 c.
- Console Redirection [Disabled] отцепляет UART от BMC целиком: ни вывода,
  ни ВВОДА (Setup по SOL недоступен; слепая навигация невозможна).
- **Above 4G off валит Mellanox (mlx4)**: 64-битные BAR-ы не помещаются
  ниже 4G → карта не стартует → умирает management-сеть (адрес ssh живёт
  на enp1s0v1001, вланы mlx4). Выглядит как «медленный бут/зависание»
  (host-powered, сеть молчит); в разведке спасало ручное перетыкание
  проводов хозяином. Практика: любые эксперименты с 4G-off на этой плате
  — закладывать запасной путь (eno1/IPMI) и не паниковать раньше времени.
- Востановление настроек без Setup: прямая запись efivar из Linux
  (chattr -i; cat new > var) + ребут — проверено, применяется BIOS'ом.
- BMC-виртуальная клавиатура (USB HID) — отдельный канал от SOL-клавиш.

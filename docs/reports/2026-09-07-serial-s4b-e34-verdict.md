# Вердикт: S4b / E34 — TermSrc сам по себе (дискриминация закрыта)

> 2026-09-07, ветка `serial-console`. Прошивка E34 (sha256 `65b18780…`,
> SerialIo-донор + TermSrc, **без glue и вопросов**) — владелец.
> Протокол: прошивка → boot → CMOS-clear → reboot.

Наблюдения владельца дословно:

- VGA: `entering setup ....` — **висит** (как на E33).
- serial (копипаст):

```
ERROR: Class:3000000; Subclass:50000; Operation: D

```

(ERROR-строка **дважды**; между ними ~15 не-ASCII байт — вероятно,
вывод на иной скорости/частичная инициализация порта.)

## 1. Итог дискриминации

E34 отличался от E33 удалением glue (и вопросов) и CMOS-clear'ом до
бута. Симптом не изменился ⇒

| Гипотеза | Статус |
|----------|--------|
| D — накопительная ConOut (мёртвые пути эры E32) | **отвергнута** — NVRAM чист, виса нет, вис тот же |
| B — glue-цепочка / fallback-путь в ConOut | **отвергнута** — glue в образе отсутствует |
| A/C — **TermSrc токсичен сам по себе** в LIVE-гибриде | **подтверждена** |

Механизм (уточнение A/C): TermSrc-чайлд создаётся BDS ConnectAll
независимо от ConOut-переменной (Supported при RDP=NULL — вердикт
E33 §2-3). При входе в Setup TSE/ConSplitter LIVE трогает
SimpleTextOut/SimpleTextIn-устройства за пределами ConOut-списка —
первый же вызов TermSrc (Reset/OutputString либо AMI-специфика
0ADFB62D/WaitForKey-контракт) роняет машину. На rd450x TermSrc живёт
в полном AMI-стеке (родные ConSplitter/TSE/SerialIo) — совместимость
контекстна, в гибриде контракт не выполняется.

Двукратный ERROR (SOFTWARE/DXE_BS_DRIVER/op 0x0D) при двух
COM-инстансах (донорский SerialIo поднимает оба порта) — ошибка в
общем пути TermSrc, не в конкретном порте.

## 2. Решения по дуге

1. **Резерв (а) «полный AMI TermSrc» закрыт** (спека-аддендум §12):
   непатченный донор нежизнеспособен в гибриде; байт-патчи §11-2
   (тип узла и т.п.) не лечат токсичность самого чайлда — смысла
   нет без полного AMI-окружения.
2. **E35 не нужен** (по дереву решений pack-отчёта S4b §3: шился бы
   только при чистом E34). Glue v3 артефакт остаётся в дереве для
   истории; рабочая glue дуги — v2 (E32).
3. **Откат хоста на E32** (`~/E32/E32-candidate-8def2850.bin`) —
   рабочая база дуги (консоль/baud/COM-переезд доказаны). После
   E34-бута: CMOS-clear уже сделан; E32-glue пересоздаст свои
   ConOut-пути с нуля.
4. **Цвет** — возвращается к рамке «свойство TSE-вывода» (контр-факт
   TODO: наш TerminalDxe `TerminalConOutSetAttribute` уже эмитит

   LIVE-AMITSE цветные атрибуты в ConOut; на rd450x шлёт). Путь:
   расследование AMITSE-рендера (отдельная спека) или путь (б).

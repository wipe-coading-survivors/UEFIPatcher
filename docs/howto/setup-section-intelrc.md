# HOWTO: добавить свой раздел в Setup (паттерн E43)

Статус: **приёмка пройдена на железе** (Huananzhi X99-TF, дуга setup-new-page
E36–E43, вердикт 2026-09-10: «стены нет, наша форма есть, значения
сохраняются»). Первоисточники: `docs/reports/2026-09-07-setup-np-e36-e37-pack.md`
(§20–21), спека `docs/superpowers/specs/2026-09-07-setup-new-page-design.md` §26.

Цель: своя страница с вопросами в существующем Setup, значения живут в NVRAM
через ребут. Рабочий путь на этой платформе — **не создавать новые формы, а
реанимировать мёртвую сток-форму** и врезать REF из живой формы.

## 1. IntelRC-стена (главный урок дуги E36–E42)

**Любая новая форма Setup-формсета на Huananzhi ломает вход в IntelRCSetup**
(меню «стенит», курсор упирается). Доказано лестницей кандидатов: форма в
сток-диапазоне id (E41), форма + $SPF-страница (E42) — стенят одинаково;
дифф против базы — единицы байт IFR. TSE строит навигацию по $PFS/AMITSE-данным,
и чужие вставки его ломают.

Отсюда паттерн E43: **ноль новых форм** — вопросы добавляются на существующую
(мёртвую) сток-форму, навигация — REF-пунктом из существующей живой формы.
Один нюанс E16-эпохи: даже «переваренную» платой новую форму без page-метаданных
TSE не показывает и не обходит — ещё одна причина не создавать форм.

На других платформах стены может не быть — тогда работает полный путь
`hii formset add` / `hii form add` + `hii page add` (исполнены движком на
живых образах в тестах, но живое меню Setup требует $PFS/AMITSE-интеграции —
см. грабли внизу).

## 2. Разведка

```bash
uefi-cli image open база.bin --mode write
uefi-cli hii form list                 # найти: живую родительскую форму
                                       # (напр. 10019 «Serial Port 1 Configuration»)
                                       # и мёртвую сток-форму (напр. 10009 — пустая,
                                       # без вопросов, недостижимая из меню)
uefi-cli hii question list <target>#10019     # занятые qid родителя
uefi-cli hii varstore list <target>           # id/размеры varstore формсета
uefi-cli hii question info <target>#10019:<qid>   # образец карты вопроса
```

Где `<target>` — Setup-модуль из колонки form_id (на HNX:
`899407d7-99fe-43d8-9a21-79ec328cac21:0x10:0`).

Проверь перед выбором id/офсетов:

- **var_store_id**: сток 1..20 заняты; 21–30 не проверены; 31+ свободны
  (для объявления новых varstore). Проще — переиспользовать сток varstore 1
  и писать в его свободные байты.
- **var_offset**: не должен пересекаться с существующими вопросами
  (сверяется по `hii question list`/`info`; на HNX хвост стора @95/96 свободен).
- **question_id**: дубли не крашер, но свои вопросы кладите высоко
  (q600+/q0x7F00+), чтобы не задеть вендорские.

## 3. Схемы

Вопросы (файл `np_questions.json`) — на мёртвую форму:

```json
{
  "questions": [
    {
      "form_id": 10009,
      "prompt": "Serial Console",
      "help": "Serial console output enable",
      "question_id": 600,
      "var_store_id": 1,
      "var_offset": 95,
      "size": 1,
      "options": [
        {"text": "Disabled", "value": 0, "default": "optimized"},
        {"text": "Enabled", "value": 1}
      ]
    }
  ]
}
```

REF (файл `np_ref.json`) — в живую родительскую форму (это и есть пункт меню):

```json
{
  "refs": [
    {
      "form_id": 10009,
      "prompt": "UEFIPatcher Setup",
      "help": "UEFIPatcher serial console settings",
      "question_id": 528
    }
  ]
}
```

Обе схемы можно совместить в одном файле (`questions` + `refs`); движок
применяет оба списка одной командой.

## 4. Применение

```bash
# вопросы на мёртвую сток-форму
uefi-cli hii question add <target>#10009 --file np_questions.json

# REF-пункт из живой родительской формы
uefi-cli hii question add <target>#10019 --file np_ref.json

uefi-cli image save patched.bin
```

Что делает движок под капотом (проверено real-image гейтами):

- вставка IFR-опкодов ONE_OF/OPTION/END внутрь тела формы (рост form-пакета —
  в слоте, u24/u32 длины и $SPF ifr-офсеты пересчитываются автоматически);
- строки prompt/help аппендятся в en-US строковый пакет;
- $SPF-запись вопроса клонируется с полями IFR (у сток-формы запись уже есть —
  страница «оживает» вместе с формой);
- REF эмитится с sentinel voff=0xFFFF перед END формы.

Инварианты для самопроверки: длина образа неизменна; дифф confined в слот
Setup-модуля (LZMA-рекомпрессия в прежний слот); вне слота 0 байт; re-parse
видит новые вопросы (`hii question list <target>#10009`).

## 5. Протокол приёмки (после прошивки)

1. Setup открывается, **IntelRCSetup входит без стены** (ключевая проверка);
2. в родительской форме появился пункт «UEFIPatcher Setup» → вход на страницу;
3. вопросы переключаются, F10 → ребут → **значения живы**;
4. остальное меню не пострадало.

## 6. Грабли

- **Не добавляйте новые формы в Setup-формсет** на платформах с AMITSE/$PFS
  навигацией — см. §1. Если очень нужно — сначала проверьте на своём образе
  одним кандидатом (форма без REF), с возможностью отката.
- `hii question add` не проверяет коллизии var_offset между формсетами —
  сверяйте карту вопросов сами (инструмент: `hii question info`).
- Если целевая форма за suppress-гейтом — сначала
  [unlock-hidden-forms.md](unlock-hidden-forms.md).
- Полный вариант с новыми формсетами/формами (`hii formset add --file schema.json
  [--ffs <guid>]`, `hii form add`, `hii page add`) технически исполнен и
  валидирован build/re-parse, но видимость в живом меню упирается в
  $PFS/AMITSE-регистрацию (E16/E17) — на живом железе используйте E43-паттерн.
- Массовый перенос готового пакета — макро `hii import --file envelope.json
  <target>` (pre-check + form add + ref step одной командой).

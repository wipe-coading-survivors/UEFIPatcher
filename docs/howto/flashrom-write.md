# HOWTO: прошивка подготовленного образа

UEFIPatcher готовит образ; заливка в чип — вручную. Ниже — рабочий опыт на
живых стендах. Главные правила: **бэкап до записи**, **понимать объём записи
для своего метода** (см. §1.2), **верификация после**.

## 1. Общие правила

1. **Бэкап до прошивки** — всегда, даже «просто проверить»:

   ```bash
   flashrom -p linux_mmap -r bios-pre.bin --layout layout.txt -i bios
   ```

2. **Объём записи зависит от метода доступа**:

   | Метод | Объём | Практика |
   |---|---|---|
   | flashrom in-system, дескриптор залочен (ASRock и т.п.) | **только BIOS-регион** по layout | полный чип не читается/не пишется: дескриптор ro, ME locked, GbE; запись дескриптора при ошибке = кирпич |
   | внешний программатор, чип в розетке (E-серия Huananzhi) | **полный образ** | полный дифф чипа, ME/дескриптор переписываются осознанно |
   | BMC/TMM (Lenovo RD450x) | **весь 16 МиБ** | BMC льёт образ целиком, включая NVRAM-регион |

3. **Определить чип точно**: старое автоопределение семейства (BV/CV/FV у
   Winbond) даёт transaction error — задавайте явный `-c` (пример ниже).
4. После прошивки первый бут может пересеять NVRAM из запечённых дефолтов —
   это ожидаемо (и часто именно цель; см.
   [asrock-baked-defaults.md](asrock-baked-defaults.md)).

## 2. flashrom in-system (пример: ASRock E3C226D2I, чип W25Q64JV)

Рабочий рецепт из живой сессии (детали:
`docs/reports/2026-09-21-asr1-226d2il-live-varmap.md`):

```bash
# layout: только BIOS-регион
cat > layout.txt <<<"0x00500000:0x007fffff bios"

# чтение бэкапа (без --noverify-all не нужно: читаем только свой регион)
flashrom -p linux_mmap -c "W25Q64JV-.Q" -r bios-pre.bin \
    --layout layout.txt -i bios

# запись; --noverify-all обязателен: без него flashrom читает весь чип
# под буфер и падает на защищённых регионах
flashrom -p linux_mmap -c "W25Q64JV-.Q" -w patched.bin \
    --layout layout.txt -i bios --noverify-all
```

Признак успеха: `Erase/write done 500000-7fffff`, `Verifying flash... VERIFIED`.

### Стена: iomem=strict

`/dev/mem mmap` на RCRB отдаёт EPERM на ядрах с `iomem=strict`. Обход без
персистентных изменений — одноразовый кварг через BLS-запись (для
ostree/bootc-хостов, где grub-конфига нет):

```bash
# добавить iomem=relaxed в options строки /boot/loader/entries/*.conf,
# перезагрузиться, прошить, вернуть конфиг обратно
```

На Fedora-хосте с grubby: `grubby --update-kernel=ALL --args=iomem=relaxed`
(и убрать после). В container-toolbox flashrom видит хост через `/run/host`.

### Что происходит с NVRAM

Запись BIOS-региона стирает **живой** NVAR-стор (если он в этом регионе).
Первый бут пересеивает значения из запечённых в образе дефолтов
(`StdDefaults`). На ASRock пересев произошёл сам, без F9; на Lenovo RD450x
после TMM-прошивки требовался F9 (Load Optimized Defaults) — платформозависимо.

## 3. Прошивка через BMC (Lenovo RD450x, TMM)

Серверные платы гиперскейлеров (Lenovo RD450x) шьются через BMC
(TMM-механика), BMC льёт весь 16 МиБ
включая NVRAM-регион — runtime-настройки слетают, восстанавливать руками в
Setup (UI-сейвы доходят) или печь в образ посевом.

- **Деградация AST2400**: после 2–3 прошивок BMC начинает сбоить — лечится
  `ipmitool mc reset warm` (BMC ~1 мин, хост не трогается).
- **SOL-клавиши**: F-клавиши через SOL идут как ESC+цифра (F1=`ESC 1`,
  F9=`ESC 9`, F10=`ESC 0`); Enter=`\r`. CSI-последовательности `ESC[xx~`
  съедаются.
- Зомби SOL-payload («already active on another session») — сначала
  `sol deactivate`, упорные — `mc reset warm`.

## 4. Верификация после прошивки

- Первый бут: значения в Setup соответствуют запечённым (или пересев
  произошёл сам);
- режим/структура меню не сломана (все разделы открываются);
- для value-патчей: слепок efivars и дифф против ожидания (метод —
  [asrock-baked-defaults.md](asrock-baked-defaults.md));
- для структуры (новые формы/страницы): вход в Setup, навигация по новому
  пункту, Save&Exit → ребут → значения живы.

## 5. Курьёз (не протокол)

Метод «чип в розетке + внешний программатор» — нормальный путь для
экспериментальной серии (Huananzhi E-серия: полный дифф чипа, быстрый
цикл итераций). Курьёз — единичное дополнение «батарейка вынута перед
каждым образом»: больше не повторялось и не требуется.

## 6. Откат

Всегда держите `bios-pre.bin` под рукой. Откат = та же запись, которой шили
(регион по layout или полный образ через программатор/BMC). Для плат с
отдельной батарейкой CMOS: полный сброс NVRAM джампером — крайняя мера при
«глухой» консоли после эксперимента с серийным выводом (прецедент — E31,
см. [serial-console-huananzhi.md](serial-console-huananzhi.md)).

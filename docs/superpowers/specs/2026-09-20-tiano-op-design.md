docs-коммитами в master по паттерну проекта; код — только в ветке).
Первоисточники: TODO.md:1504–1523 (**BLOCKER: Tiano-декомпрессия —
заглушка**; разведка ASRock-образов 2026-09-03 с проверкой оракулом),

## Контекст и проблема

`decompress_tiano` — заглушка (`Err(Unsupported)`, `decompress.rs:23`). Все
Compressed-секции с алгоритмом 1 (EFI standard) на ASRock-образах не
разворачиваются: парсер строит узлы секций (образы открываются, полные
деревья FV/файлов/секций), но `children` пусты и весь DXE-контент включая
Setup/HII непрозрачен → `hii form list` пуст, вопросы/гейты/set-value
недоступны. Владельческая цель цикла — смена дефолтов (SOL, Above 4G
Decoding) на ASRock без AMIBCP.

Разведка 2026-09-03 (проверена C-оракулом):

- все 228 сжатых секций C275D4I3.20 — **EFI-standard 4-bit** вариант
  (`EfiDecompress`, EFIPBIT=4); 5-битный Tiano — 0/228 живых секций;
- Rust-крейт `efi-compress` 0.2.0 на реальной секции валит оба варианта
  («bad Huffman table») — использование исключено;
- эталон `refs/UEFITool-ai-fork/common/Tiano/EfiTianoDecompress.c`
  (единый декодер, параметр pbit 4/5) собран и проверен → 228/228;
- компрессор `EfiTianoCompress.c` там же в refs — материал этапа 2;
- фикстуры `/tmp/c275_secs/` утрачены (tmpfs) — пересоздаются (§3).

Каналы интеграции уже разведаны и сходятся в одну точку:
`parse_section` Compressed (algo 1 → `decompress::decompress(body[5..], 1)`,
parser/section.rs:41) и guided-секция с GUID `A3128AD8-…`
(`is_tiano_guid` → Standard, parser/section.rs:90–117). Корпус C275 целиком
pbit=4 (GUID `A3128AD8` — EFI standard compression GUID), но algo-1 поток
не несёт pbit-различителя: живой гейт показал, что 226D2IL3.x содержит
algo-1 секции Tiano pbit=5. Поэтому `decompress_tiano` пробует варианты по
очереди — EFI (pbit=4), при отказе Tiano (pbit=5), как UEFITool
(` ref: UEFITool-ai-fork/utility.cpp:243`); preparse-различение «оба
декодируются» не делаем (` ref: ffsparser.cpp:3292`).

## Решения владельца (брейншторм 2026-09-20)

- **Ступенчатый скоуп.** Этап 1 (эта спека): порт декодера + интеграция +
  гейт на живых образах. Этап 2 (отдельная спека, решение после этапа 1):
  компрессор `EfiTianoCompress.c` и слот-фит — только если по результатам
  этапа 1 перезапись сжатой копии StdDefaults действительно нужна (на
  HNX/450x паттерн «править raw-копию + LZMA-копию», LZMA уже рекомпрессим;
  возможно, raw-копии на ASRock достаточно).
- **Подход A — прямой порт эталона в чистый Rust**, без FFI и без чужих
  крейтов.
- **Требования к реализации:** 1) без `unwrap()`/`expect()` в не-тестовом
  коде; 2) максимально раст-идиоматично, но без бессмысленного фанатизма.
- NVRAM-метка (TODO:3206) — отдельный микро-коммит после Tiano, в цикл не
  входит.

## §1 Декодер: `crates/uefi-engine/src/tiano.rs`

Прямой порт `EfiTianoDecompress.c` (единый LZ77+Huffman декодер,
референс-комментарии `ref: …/EfiTianoDecompress.c:<функция>` по конвенции
проекта). Контракт:

```rust
pub enum Pbit { Efi /* =4 */, Tiano /* =5 */ }
pub fn decompress(data: &[u8], pbit: Pbit) -> Result<Vec<u8>, DecompressError>
```

- вход — payload секции целиком: заголовок `EFI_TIANO_HEADER`
  (u32 comp_size, u32 orig_size LE) + сжатый поток; ожидаемый размер выхода
  берётся из orig_size (несовпадение размеров/границы → `Corrupted`);
- любой выход за границы входа/выхода и любая неконсистентность таблиц
  Huffman — `Err(DecompressError::Corrupted)`, без паник: битовый ридер и
  построитель таблиц возвращают `Result`, `unwrap()` запрещён (владельческое
  требование);
- раст-идиоматика: битовый ридер — структура с методами `read_bit`/
  `read_bits(n)`; таблицы — индексные массивы без unsafe и без ручной
  арифметики указателей; возврат `Vec<u8>` заранее аллоцированный под
  orig_size;
- pbit — compile-time константа выбора варианта (как параметр эталона);
  фикстуры покрывают только `Pbit::Efi` (0 живых секций на 5-бит),
  поддержка `Pbit::Tiano` переносится из эталона как есть, без отдельного
  теста;
- модуль не зависит от остальных модулей крейта (кроме типа ошибки) и не
  тянет новых зависимостей Cargo.

## §2 Интеграция: `decompress.rs` + парсер

- `decompress_tiano(data)` (`decompress.rs:23`) перестаёт быть заглушкой:
  вызывает `tiano::decompress(data, Pbit::Efi)`, при отказе —
  `tiano::decompress(data, Pbit::Tiano)` (порядок как у UEFITool, см.
  «Контекст»), итоговая ошибка пробрасывается как есть
  (`Corrupted`/`Unsupported` уже в `DecompressError`);
- парсер, билдер, TUI, RPC — **без правок**: оба канала уже вызывают
  `decompress::decompress(payload, 1)`; поведение при отказе не меняется
  (`tracing::warn` + пустые children);
- тест `decompress_tiano_unsupported_in_cycle1` (`decompress.rs:61`)
  заменяется на позитивный (фикстура §3) — заглушки больше нет;
- билдер: dirty-рекомпрессия Tiano остаётся ошибкой
  (`builder/mod.rs:20` — «unsupported algorithm»), round-trip
  немодифицированных образов байт-в-байт по сырому хранению узлов не
  затрагивается. Расширение recompress-канала — этап 2.

## §3 Фикстуры и оракул

- **C-оракул**: `hack/tiano-oracle.c` — `EfiTianoDecompress.c` + мини-main
  (stdin: payload; argv: pbit; stdout: decompressed), сборка `cc`
  одноразовой командой (документируется в спеке плана; в репо — только
  исходник оракула, артефакты сборки не коммитятся).
- **Извлечение секций** — существующие средства без нового кода: цели
  algo-1 перечисляются командой `node list` (main.rs:127), payload
  дампится `node extract <target> --body-only` (main.rs:182). Извлечение
  работоспособно уже сегодня (узлы Compressed-секций строятся с телами) и
  проверкой декодера не является.
- **Генерация**: корпус фикстур — с `refs/amibcp/C275D4I3.20` (все 228
  algo-1 секций; скрипт принимает любой образ, при необходимости
  прогоняется и на 226D2IL3.x). Коммит в
  `crates/uefi-engine/tests/fixtures/tiano/` — 3 представительные пары
  (минимальная, медианная по размеру, максимальная); полный корпус всех
  трёх образов в репо не тащим — он покрывается real-image гейтом §4.
- `/tmp/c275_secs/` не восстанавливаем — схема путей выше его заменяет.

## §4 Тесты

- **Unit (коммитимые)**: `tiano.rs` — decode каждой фикстуры §3 ==
  `.expected` байт-в-байт; негативные (обрезанный поток, мусорный заголовок,
  orig_size=0) → `Corrupted`, без паник; чтение за концом входа → `Corrupted`.
  `decompress.rs` — `decompress(data, 1)` на фикстуре == expected
  (замена заглушечного теста).
- **Real-image гейт** `tests/real_image_asrock.rs` (`#[ignore]`, по образцу
  `real_image.rs`; пути `../../../refs/amibcp/<имя>`): каждый образ —
  полный парс; для **каждой** Compressed-секции algo 1 c непустым payload
  children непусты; находится Setup-модуль с непустым набором IFR/HII-секций
  (FormSet-GUID из образа фиксируется в тесте); round-trip сборки ==
  оригинал байт-в-байт. Счётчики секций (228 на C275 и найденные на
  226D2IL3.x) выводятся в выводе теста и фиксируются в TODO-отчёте.
- **Живой CLI-гейт** (ручной, вне cargo): `uefi-cli open C275D4I3.20` →
  `hii form list` непуст; поиск форм/questions SOL (Console Redirection /
  Serial Port) и Above 4G Decoding; находки — в TODO-отчёт цикла. Это вход
  этапа 2.

## §6 Границы

- **Этап 2 (компрессор) — вне этой спеки**: порт `EfiTianoCompress.c`,
  стратегия слот-фита (EDK2-поток может выйти крупнее AMI-шного слота),
  dirty-рекомпрессия в билдере, запись дефолтов. Открывается отдельной
  спекой после гейта этапа 1.
- NVRAM-метка (TODO:3206) — отдельный микро-коммит, не в этой ветке.
- LZMA-канал, guided-атрибуты, TUI — не трогаем.

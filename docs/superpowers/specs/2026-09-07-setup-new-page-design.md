# Спека: дуга «setup-new-page» — своя подстраница Setup через goto-вход

> Дизайн-документ, 2026-09-07, ветка `setup-new-page` (от origin/master
> `d8feaaa`). Статус: решение владельца 2026-09-07 — новая страница
> **не верхнего уровня**: живёт там же, где текущие serial-настройки, —
> Advanced → Super IO Configuration → Serial Port 1 Configuration (форма
> 10019), вход — goto-пункт с живой страницы. Подход (указание владельца):
> задача сложная → спека + роадмап + пре-чеки; разведка — «мощная, без
> TDD-плана, но с журналом» по прецеденту hijack v1/v2/v2.1 (спека E18 →
> журнал tse-bridge → спека v2 → план). Детальный TDD-план — только на
> фазу P, после ревью спеки и закрытия R.
> Источники: `docs/reports/2026-09-04-tse-bridge-recon.md` §3/§4/§9
> (карта $SPF, геометрия аппенда, карта каналов рендера), hijack-v2/v2.1
> (E24–E29, `docs/reports/2026-09-05-hijack-v2-e29.md`), S3/E31
> (`docs/reports/2026-09-06-serial-s3-e31-pack.md` — $SPF-аппенд вопросов
> доказан железом), S4b/E34 (дуга serial на E32-базе).

## 1. Контекст и задача

Hijack-дуга доказала на железе полный рецепт захвата **существующей**
страницы (6/6 каналов рендера, E24–E29). Дуга S3 доказала живучесть
**аддитивного** $SPF-аппенда: op `hii question add` добавляет вопрос в
живую форму целиком (IFR-сплайн + строковые аппенды en-US + 72B-запись +
пул-контрол хелпа + клон страницы с новым контролом + repoint слота +
bump длины контейнера) — E31: вопросы рендерятся, help-панель наша,
дефолты работают, значения сохраняются.

Не доказано одно: **рендер формы, которой нет в таблице страниц $SPF**.
E16 (form-add) показал «стену» — но наблюдалась только видимость в
меню (меню TSE строится из $SPF), goto-вход в форму-цель тогда не
проверялся. Уточнение владельца снимает самый дорогой канал дуги:
пункт верхнего уровня (регистрация в меню) **не нужен** — достаточно
goto-вопроса на живой странице 10019. Это обходит недекодированную
таблицу 0x180–0x354 в части меню и сводит открытые вопросы к четырём
(tse-bridge §4) плюс один новый — goto-рендер цели.

## 2. Карта каналов: доказанное и открытое

| Канал | Источник | Статус |
|---|---|---|
| вопрос one_of на живой странице (prompt/опции/дефолты/сохранение) | IFR + $SPF-аппенд | **доказан** (E30/E31) |
| help вопроса | $SPF запись s14 + пул-контрол | **доказан** (E26, E31 — «help-панель наша») |
| строковые аппенды | en-US (+ bare/PE32-resource каналы) | **доказан** (E24–E26, E31; x-AMI не нужен) |
| клон страницы + repoint слота + bump длины | $SPF-аппенд | **доказан** (E31, iron) |
| suppress/видимость | IFR suppress-if | неприменимо — свой IFR без suppress |
| goto-пункт на живой странице | IFR REF-вопрос (+ тип его $SPF-записи?) | **открыт** (R1/E36) |
| рендер goto-цели без страницы в $SPF | обработчик goto в AMITSE | **открыт — главный вопрос E36** |
| заголовок страницы-цели | $SPF title-id@+0xE страницы | механизм доказан (E24–E26); для новой страницы = P3 |
| пункт меню верхнего уровня | таблица страниц $SPF + меню | **не нужен** (решение владельца) |

## 3. Цели и не-цели

**Цели:**

1. Видимая и работающая подстраница: goto-пункт «UEFIPatcher …» на
   форме 10019 → своя форма-цель с 1–2 вопросами one_of (значения в
   varstore `Setup`, Load Optimal → дефолты).
2. Закрыть главный вопрос дуги: рендерит ли TSE goto-цель без записи
   в таблице страниц $SPF (E36 — дешёвый железный дискриминатор).
3. Если страница нужна — движковый райтер регистрации страницы по
   геометрии §4 tse-bridge (нулевой слот @0x354 + count@0x60), поверх
   примитивов `spf.rs` (клон/repoint/bump уже есть и доказаны E31).
4. Обновить карту каналов TSE (§2) вердиктами E36/E37 — аддендумы.

**Не-цели:**

- пункт верхнего уровня меню (снято владельцем; регистрация в меню —
  вне дуги, материалы R сохраняются);
- переименование сток-страниц (hijack-v2 уже умеет);
- новые типы вопросов кроме ref/one_of; перенос q512/q513 на новую
  страницу (возможно позже, отдельной правкой);
- serial-дуга (цвет, CSM-редирект — парковка по вердикту E34).

## 4. Фаза R — разведка с журналом (без прошивок)

Формат — прецедент tse-bridge: побайтовая статика + независимые скрипты
+ кросс-чек живым движком; выход — журнал-отчёт
`docs/reports/2026-09-0X-setup-page-recon.md` + аддендум этой спеки.
Прошивок нет; всё на `refs/fw/HNX99TF_200525_original_E5C88C6F.bin` и
эталоне `refs/amibcp/450x-4g-default.bin` (MNX99MR9A, оба — только
чтение). Скрипты tse-bridge §6 (`/tmp/tse-bridge/*`) при утере /tmp
переизвлекаются по рецептам §6 отчёта.

**R1 — сравнительная геометрия $SPF: LIVE ↔ MNX99MR9A.** У референса
есть живые goto-вложенные страницы (Advanced-подстраницы) — посмотреть,
как зарегистрирована страница 2-го уровня: поля структуры (marker@+8,
seq@+0x10, B@+0x12, u32@+0x18), типы их записей, занят ли «нулевой
слот» таблицы. Ответы закрывают неизвестное (4) и дают тип $SPF-записи
goto-вопроса (сток-REF в форме 10002 → запись по qid).

**R2 — дизасм AMITSE** (блоб MPDT @0xA780C0, 299 КБ, сохранён
`/tmp/tse-bridge/mpdt_a780c0.bin`; «Aptio Setup Utility», строк
формсетов не содержит — кандидат закрыт §8 tse-bridge). Вопросы:

- (i) читатель таблицы страниц: цикл по count@0x60 или zero-scan слотов
  → неизвестное (1). Геометрия §4 (слот+бамп) валидна в обеих
  семантиках, но дизасм снимет и риск валидации длины/регионов;
- (ii) семантика зоны 0x180–0x354 (вторая индексная таблица) →
  неизвестное (3): нужна ли запись там для рендера goto-цели;
- (iii) **обработчик goto**: как резолвится форма-цель — по IFR напрямую
  или через страницу $SPF; что происходит с формой без записи
  (fallback-рендер / пусто / игнор goto) → главный вопрос E36;
- (iv) записи 2-го класса [0x5AD20..0x73F0C) → неизвестное (2):
  относится ли к чужим формсетам (IntelRC) и не задевает ли наш путь.

**Критерий выхода из R:** по каждому из (1)–(4) и goto-вопросу —
«закрыто статикой» либо «дискриминируется на железе E36/E37». Если R
закрывает goto-вопрос однозначно — E36 можно пропустить и идти в E37
сразу (решение фиксируется в аддендуме).

## 5. Фаза P — пре-чеки движка (TDD-план отдельным документом)

План `docs/superpowers/plans/2026-09-0X-setup-new-page-prechecks.md`
пишется после ревью спеки и закрытия R (состав задач зависит от
результатов R). Ожидаемый состав:

- **P1 ref-вопрос**: расширение `hii question add` вариантом `ref`
  (schema: `{type:"ref", form_id, prompt, help, question_id}` — без
  varstore); IFR — `emit_ref` (OP_REF, уже в `ifr_builder.rs`);
  $SPF-аппенд — переиспользовать S3-конвейер (запись+контрол+клон
  страницы 10019+repoint), тип записи — по R1 (дефолт: клон type-6 —
  E31 доказал его живучесть; достаточность для goto покажет E36).
  Гейты: юнит + round-trip REF на живом образе.
- **P2 форма-цель**: `hii form add` (механика E16, bare/PE32-resource
  каналы) — уже умеет; выбрать свободные form-id (по `collect_forms`
  на LIVE; кандидат > 10029, напр. 0x2775), qid (0x202 goto; 0x258+
  вопросы) и офсеты varstore id 1 (после 0x5E, по `scan_question_slots`
  — не наступить на сток-вопросы Super IO).
- **P3 райтер страницы**: новый код поверх `spf.rs`: клон страницы
  10019 (учесть pool-style конвенцию её списков — E31-контингенси) +
  патч form-id@+0xA / title-id@+0xE / seq@+0x10 (значения — по R1) +
  запись указателя в нулевой слот @0x354 + bump count@0x60 188→189 +
  `bump_container_length`. Гейты: юнит на синтетике (прецедент
  `synth_container`) + инварианты на LIVE.
- **P4 LZMA-запас**: пересчёт слота 0xC2C4 (декомпрессат 0x7719C) с
  новыми аппендами (страница ~0x24+4·N + записи 72·N + контролы + IFR +
  строки); механика пересборки доказана (E18/E31).
- **P5 real-image гейт дуги**: полный реплей на E5C88C6F (цепочка E32 +
  goto + форма [+ страница]) с инвариантами по прецеденту s4*:
  зонный дифф, round-trip save→open→save, q-round-trip, $SPF-инварианты
  (count/слот/длина контейнера), стабильность rebuild.

## 6. Лестница кандидатов (база — E32-конвейер)

База каждого кандидата — полный движковый реплей на E5C88C6F: цепочка
E32 (SerialIo-донор + TerminalDxe + glue v2 + q512/q513) + правки дуги.
Протокол — прецедент S4a/S4b: один семантический дифф на кандидат,
гейт P5 → `hack/fv_audit.py` → зонный дифф → флеш (только владелец) →
вердикт дословно → аддендум спеки + roadmap. Откат — рефлеш
`~/E32/E32-candidate-8def2850.bin` (или E5C88C6F).

- **E36 «goto-only»** — главный дискриминатор. Состав: E32 + REF-вопрос
  q514 «UEFIPatcher Serial Settings» в конец формы 10019 (S3-механика) +
  форма-цель (P2) с 1–2 one_of + строки en-US. **Без** записи страницы в
  $SPF. Исходы:
  - **(a)** пункт рендерится, вход открывает страницу, вопросы работают
    → канал goto доказан, регистрация страницы не нужна для
    функциональности (только заголовок/косметика — E38 опционально);
  - **(b)** пункт рендерится, вход — «стена»/пустая страница →
    goto-пункт живёт из IFR, страница — из $SPF → E37;
  - **(c)** пункт не рендерится → нужна $SPF-запись goto-вопроса
    (тип — R1; если R1 молчит — итерация записи) → E36b → затем E37;
  - **(d)** вис/ERROR → откат на E32, разбор статикой (прецедент E33);
- **E37 «регистрация страницы»**: E36 + P3 (слот+count+bump, поля по
  R1). Ожидание: полный рендер страницы + заголовок наш (title-id@+0xE).
- **E38 (опционально, косметика)**: help-контролы страницы, декор,
  перенос q512/q513 на новую страницу.

## 7. Риски и контингенси

- **R не отвечает на goto-вопрос** → E36 обязателен; он дёшев (1 флеш,
  один семантический дифф против E32).
- **Конвенции page-list** (475 pool-block против 4736 direct, базовая
  страница 10019 — pool-style; E31-контингенси) — уже пережито железом
  E31 (клон с direct-указателями работал); клон для E37 — та же
  конвенция.
- **zero-scan vs count (1)**: слот+бамп валиден в обеих семантиках;
  остаточный риск — валидация TSE длин/регионов → R2(i).
- **Записи 2-го класса (2)**: вероятны чужие формсеты (IntelRC) — наш
  путь 1-го класса; не блокирует, R2(iv) подтверждает.
- **LZMA-запас исчерпан** → пересборка слота с ростом (механика
  доказана E18, оба слота).
- **Коллизии form-id/qid/офсетов** — сканы P2, гейт P5.
- **Вис Setup** (прецедент E33): риск низкий — правки данных TSE, не
  кода DXE-драйверов; ветка отката обязательна в pack-отчёте каждого
  кандидата.

## 8. Критерии успеха дуги

- **Минимум**: goto-пункт на 10019 ведёт на нашу страницу, вопросы
  рендерятся и сохраняются (Load Optimal → дефолты) — E36(a) или E37.
- **Полный**: + заголовок страницы наш (E37) и help (E38).
- **Наработка**: закрытая карта goto-каналов TSE (§2), движковые
  op-расширения (ref-вопрос, регистрация страницы) с гейтами, прецедент
  «своя страница без жертвы» для будущих циклов.

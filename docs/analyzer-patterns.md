# Шаблоны анализатора — живой справочник

Реестр известных шаблонов (сигнатуры, структуры, таблицы) для
будущей команды `analyze` (рекон-кит, см. TODO). **Это не журнал**:
сюда попадают только оформленные повторяемые шаблоны, вскрытые по
итогам цикла или реверс-сессии — по одной записи: сигнатура,
структура, где найдено, как детектить, первоисточник.
Промежуточные находки/рассуждения — в спеку/отчёт цикла, не сюда.

Формат записи: `P<n>. Имя` + поля. Оффсеты в записях — от
начала структуры, если не сказано иное.

---

## P1. $SPF — компилированные страницы AMITSE

- **Где найдено**: 450x, FFS-файл B1DA0ADF-4F77-4070-A88E-BFFE1C60529A
  (Aptio Setup Browser), секция 0x18 FREEFORM_SUBTYPE_GUID с
  subtype GUID FE612B72-203C-47B1-8560-A66D946EB371, 498 820 б.
- **Сигнатура**: magic `"$SPF"` (24 53 50 46) по смещению +0x10
  тела секции (после 16-байтного subtype GUID).
- **Структура** (оффсеты от magic): хедер @+0x28..0x44 — u32-оффсеты
  под-блобов; таблица страниц @+0x60 = `{u32 count, u32 offs[count]}`;
  запись страницы: `u16 fsIdx@+8, u16 formId@+0xa, u16 selfIdx@+0x10,
  u16 flags12@+0x12, u32 flags@+0x14, u32 childCount@+0x1c,
  u32 ctlOffs[]`; контролы @+0x83c4 (по хедеру); каталог
  переменных и блоб формсетов — по хедеру.
- **Детект**: секция 0x18 + subtype FE612B72… → проверить magic.
- **Первоисточник**: спека positional-insert, аддендум «Фронт 1»
  (2026-09-22); дампы `refs/amibcp/probes/tse-b1da0adf/spf.bin`.

## P2. Stride-таблицы `{GUID, u64, нулевые хвосты}`×0x20 в TSE PE

- **Где найдено**: 450x, PE того же файла B1DA0ADF: @0x1a80
  (фаза-1 «показывать»), @0x1b40 (hide-таблица), @0x1ba0
  (порядок корневого бара), @0x1c00 (динамические формсеты).
- **Структура**: ≥2 записей шагом 0x20: `{GUID(16), u64 form-id,
  u64 0}`; блок завершается полностью нулевой записью.
- **Детект**: скан на серии выровненных записей — GUID валиден
  (версия/вариант не обязательны), form-id мал (<0x10000), хвосты
  нулевые, терминатор — 32 нуля. GUID-ы записей обычно совпадают
  с формсетами образа.
- **Первоисточник**: там же; именно этот паттерн вскрыл гейт
  вкладки IntelRCSetup (зануление записи @0x1b40, артефакт v3).

## P3. Каталог переменных $SPF — записи `{GUID, имя[64] UCS-2, attrs, size}`

- **Где найдено**: внутри $SPF (P1) — блоб по хедеру
  (@+0x7659c в 450x): `{u32 count, u32 offs[]}` → записи длиной 0x7C:
  `GUID(16), имя UTF-16LE[64], u32 attrs@+0x60, u32 @+0x64,
  u32 size@+0x78`.
- **Детект**: массив u32-оффсетов + записи 0x7C с UTF-16 именем,
  оканчивающимся NUL; size поля правдоподобны (байты переменной).
- **Сверка**: size записей совпал с живым NVRAM (ServerSetup=479,
  IntelSetup=5744) — пригодно для кросс-проверки дампов.
- **Первоисточник**: спека positional-insert, «Фронт 1»/«C-тест».

## P4. Записи `{GUID, ASCII-имя}` — карта GUID→имя-переменной

- **Где найдено**: TSE PE @0x1d30+ (шаг 0x44): {EC87D643,
  "UsbMassDevNum"}, {EC87D643, "UsbMassDevValid"}, {EC87D643,
  "UsbSupport"}.
- **Детект**: валидный/повторяющийся GUID + NUL-terminated ASCII
  имя сразу за ним.
- **Первоисточник**: спека positional-insert, «План C —
  препарация TSE».

## P5. SMCI NVAR-магазин (Supermicro NVRAM в RAW-FFS)

- **Где найдено**: 450x, FV gEfiSystemNvDataFvGuid (@0x800000
  образа прошивки / окно 0x800000+ чипа), RAW-файл
  CEF5B9A3-476D-497F-9FDC-E98143E0422C.
- **Структура**: поток записей: `{state-байт, [GUID(16) при первом
  использовании], "NVAR", u16 size (LE, от магика), u16 csum,
  attrs-байт (0x82 + GUID-index), ASCII имя NUL, data}`; общая
  GUID-таблица в начале магазина (GUID-index из attrs указывает
  в неё).
- **Детект**: RAW-FFS c GUID CEF5B9A3… → поток "NVAR"-магиков.
- **Первоисточник**: спека positional-insert, «C-тест» (живой
  flashrom-дамп 20260922).

## P6. GUID-defined LZMA-секции (семейство)

- Реестр GUID-ов уже живёт в движке: `uefi-engine/src/ffs.rs`
  (`lzma_guid` EE4E5898-3914-4259-9D6E-DC7BD79403CF, lzma_hp
  0ED85E23…, lzma_ms BD9921EA…, lzmaf86 D42AE6BD…, crc32).
- **Детект для анализатора**: секция 0x02 с GUID из реестра ffs.rs
  → сообщать «сжатая LZMA, внутри — дерево секций».
- Анализатору не дублировать константы, а брать из ffs.rs.

## P7. AMI baked NVRAM-шаблоны в PE драйвера

- **Где найдено**: 450x, PE @image 0xe35c30 (кандидат ABBCE13D,
  IntelRCSetup-драйвер): серии `{GUID формсета, attrs, имя
  переменной, данные-дефолты}` (области 0xe35eb0…0xe90ac0).
- **Детект**: в PE за структурой EFI_VARIABLE_AUTHENTICATION…
  ищем пары {известный GUID формсета + имя переменной Setup/
  IntelSetup/…} с правдоподобными attrs.
- **Первоисточник**: спека positional-insert, «План C —
  препарация TSE» (обнаружены при поиске источника IntelSetup).

## Стандартные магики (контекст)

`_FVH` @FV+0x28; `MZ`/`PE\0\0` (PE32-секция 0x10); `VZ` (TE,
0x12); `NVAR` (внутри P5); `"$SPF"` (P1). Движок уже парсит
большинство — анализатору достаточно ссылаться на парсер.
